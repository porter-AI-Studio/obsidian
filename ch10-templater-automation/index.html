Templater 與自動化：告別重複勞動

讓模板「活起來」：從靜態插入到動態腳本

重複操作的隱性成本

你每天打開 Obsidian 新建一則筆記，然後做同樣的事：輸入今天的日期、貼上「## 待辦」的標題、填入本週週數、寫上星期幾。這些動作每次不超過 30 秒，但一年 365 天加起來就是好幾個小時——更重要的是，每一次這樣的重複都在打斷你真正應該做的事：思考和寫作。

Obsidian 內建的 Templates 核心插件只能做靜態插入——你定義一個模板，它就原封不動地貼進去。想讓模板自動帶入今天的日期？不行。想讓不同的筆記類型自動套用不同的格式？不行。

Templater 解決了這個問題。它讓模板從「靜態文字」變成「動態腳本」——每次插入時，模板裡的變數會被即時求值，填入當下的時間、檔案名稱、系統資訊，甚至執行自訂的 JavaScript 邏輯。

Templater 是什麼，跟內建 Templates 有何不同

安裝路徑：設定 → 社群插件 → 搜尋 Templater → 安裝並啟用。啟用後在設定裡指定一個「模板資料夾」（建議新建 Templates/ 資料夾）。

兩者最核心的差異：

  • 內建 Templates：純靜態。模板裡的 {{date}} 是唯一的動態變數，而且只能插入，無法計算。
  • Templater：動態腳本引擎。語法是 <% ... %>，支援 JavaScript 運算、條件判斷、迴圈，以及豐富的內建模組（日期、檔案、系統、游標控制等）。

安裝後的第一個設定：在 Templater 的設定頁面，打開「Trigger Templater on new file creation」選項。這樣每次新建筆記時，Templater 都會自動詢問要套用哪個模板——或是根據你設定的規則自動套用，完全不需要手動觸發。

tp.* 函數分類全覽

基礎語法：四大模組

Templater 的語法都包在 <% ... %> 裡。四個內建模組覆蓋了絕大多數使用情境：tp.date（日期時間）、tp.file（檔案資訊）、tp.system（系統互動）、tp.user（自訂函數）。

tp.date — 日期與時間

<% tp.date.now("YYYY-MM-DD") %>          → 今天日期，如 2026-06-20
<% tp.date.now("YYYY/MM/DD") %>          → 斜線格式，如 2026/06/20
<% tp.date.now("dddd") %>                → 星期幾，如 Friday
<% tp.date.now("WW") %>                  → 本年第幾週，如 25
<% tp.date.now("YYYY-MM-DD", 1) %>       → 明天
<% tp.date.now("YYYY-MM-DD", -7) %>      → 7 天前
<% tp.date.now("YYYY-MM-DD HH:mm") %>   → 含時分，如 2026-06-20 09:30

tp.file — 檔案資訊

<% tp.file.title %>        → 當前筆記的檔案名稱（不含 .md）
<% tp.file.folder() %>     → 當前筆記所在資料夾名稱
<% tp.file.path() %>       → 完整路徑，如 Projects/design-review.md
<% tp.file.creation_date("YYYY-MM-DD") %>  → 檔案建立日期

tp.system — 系統互動

<% await tp.system.prompt("輸入主題：") %>
→ 彈出輸入框，讓你在建立筆記時填入一個值

<% await tp.system.suggester(["讀書", "工作", "個人"], ["book", "work", "personal"]) %>
→ 彈出選單，選一個選項（第一個陣列是顯示文字，第二個是實際值）

tp.system 讓模板在建立時變成一個「填問卷」的流程——每次新建筆記，Templater 依序問你幾個問題，自動填入正確的欄位，不需要手動去找 frontmatter 的位置逐一修改。

tp.file — 進階用法

<% tp.file.cursor() %>            → 模板套用後，游標自動跳到此位置
<% tp.file.cursor(1) %>           → 第一個 Tab 停駐點（可設多個，按 Tab 鍵切換）
<% tp.file.cursor(2) %>           → 第二個 Tab 停駐點

<% tp.file.include("[[Other Note]]") %>   → 嵌入另一個筆記的內容（類似 Transclude）
<% await tp.file.move("/Projects/new-name") %>  → 模板執行後自動重新命名並移動檔案

tp.user — 掛載自訂函數

tp.user 讓你把常用的 JavaScript 函數寫成獨立檔案，在任何模板裡重複呼叫。在 Templater 設定裡設定「User Script Functions Folder」後，該資料夾裡的 .js 檔案就會以 tp.user.檔名() 的形式暴露給所有模板。 

// 存成 Scripts/utils.js
function utils(tp) {
  return {
    // 取得本週的星期一日期
    weekStart: () => {
      const d = new Date();
      const day = d.getDay();
      const diff = d.getDate() - day + (day === 0 ? -6 : 1);
      return new Date(d.setDate(diff)).toISOString().split('T')[0];
    },
    // 格式化專案 ID
    projectId: (name) => name.toLowerCase().replace(/\s+/g, '-')
  };
}
module.exports = utils;

// 在模板中呼叫：
// <% tp.user.utils(tp).weekStart() %>
// <% tp.user.utils(tp).projectId("My Project") %>

Startup Template：Obsidian 開啟就自動執行

Startup Template 是 Templater 的隱藏強力功能——你指定一個模板，每次 Obsidian 啟動時自動執行它的腳本。最實用的用法是「自動建立今天的日記」：如果今天的日記不存在，就在正確的位置自動建立一份；如果已存在，就什麼都不做。 

<%*
// === Startup Template ===
// 設定位置：Templater 設定 → Startup Templates → 選擇此檔案
// 每次 Obsidian 啟動時自動執行

const today = tp.date.now("YYYY-MM-DD");
const todayFile = app.vault.getAbstractFileByPath(`Journal/${today}.md`);

// 如果今天的日記不存在，自動建立
if (!todayFile) {
  const templateFile = app.vault.getAbstractFileByPath("Templates/Daily Note.md");
  if (templateFile) {
    await tp.file.create_new(templateFile, today, true, app.vault.getAbstractFileByPath("Journal"));
    new Notice("已建立今日日記：" + today, 4000);
  }
}
%>

設定方式：Templater 設定 → Startup Templates → 點「+」新增 → 選擇剛才的腳本檔案。之後每次開啟 Obsidian，這個腳本就會靜默執行——如果今天的日記不存在，Journal 資料夾裡就會多出一份以今天日期命名的筆記，完全不需要你手動建立。

Startup Template 不要放太多邏輯：Obsidian 啟動時 Startup Template 會立即執行，如果腳本有錯誤或執行時間過長，會影響啟動速度甚至造成卡頓。建議只放輕量的「如果不存在就建立」邏輯，複雜的批次操作還是放在獨立模板裡手動執行。

與 Dataview 組合：模板插入 Metadata

Templater 和 Dataview 是 Obsidian 最強大的搭檔組合。Templater 負責在新建筆記時填入結構化的 frontmatter（如日期、類型、狀態），Dataview 則負責後續跨筆記查詢。用 Templater 插入的每一筆 metadata，都成為 Dataview 可以查詢的資料點。

以每日筆記為例：如果模板在 frontmatter 裡插入了 mood 和 energy 欄位，你就可以在週報裡用 Dataview 自動產生這週的心情趨勢表格。

type: daily

Templater + Dataview 設計原則：讓 Templater 負責「輸入端」——每次新建筆記時，用 prompt/suggester 確保 metadata 格式統一；讓 Dataview 負責「輸出端」——跨筆記聚合、排序、過濾。兩者分工明確，才能讓知識庫真正「活起來」。

進階：用 Templater 腳本自動歸類筆記

Templater 真正的威力在於 <%* ... %> 語法——進入「腳本模式」，可以執行完整的 JavaScript 程式碼，包括讀取 Vault 裡所有筆記、移動檔案、呼叫 Obsidian API。

以下是一個實用的自動歸類腳本，可以掃描整個 Vault，把符合關鍵字條件的筆記批次移動到指定資料夾： 

<%*
// === 配置（每次使用前修改這裡）===
const 配置 = {
  模擬模式: true,                // true=只預覽不實際移動，false=真正移動
  搜尋關鍵字: "環境數據",         // 要篩選的關鍵字
  目標資料夾: "Pages/環境數據",   // 移動到的目標資料夾
  排除目錄: ["Templates", "Assets"],
  搜尋範圍: {
    檔案名: true,    // 搜尋檔案名稱
    正文: false,     // 搜尋正文內容（較慢）
    元數據: false    // 搜尋 YAML frontmatter
  }
};

// === 主流程 ===
const 所有筆記 = app.vault.getMarkdownFiles();
const 匹配清單 = [];

for (const 檔案 of 所有筆記) {
  // 排除目錄檢查
  if (配置.排除目錄.some(d => 檔案.path.includes(d + '/'))) continue;
  if (檔案.path.startsWith(配置.目標資料夾)) continue;

  if (配置.搜尋範圍.檔案名 && 檔案.name.includes(配置.搜尋關鍵字)) {
    匹配清單.push(檔案);
    continue;
  }

  if (配置.搜尋範圍.正文 || 配置.搜尋範圍.元數據) {
    const 內容 = await app.vault.read(檔案);
    if (內容.includes(配置.搜尋關鍵字)) 匹配清單.push(檔案);
  }
}

// 移動或預覽
let 成功 = 0;
for (const 檔案 of 匹配清單) {
  const 新路徑 = 配置.目標資料夾 + '/' + 檔案.name;
  if (配置.模擬模式) {
    console.log('[預覽] ' + 檔案.path + ' → ' + 新路徑);
    成功++;
  } else {
    await app.fileManager.renameFile(檔案, 新路徑);
    成功++;
  }
}

const 狀態 = 配置.模擬模式 ? '預覽' : '完成';
new Notice(狀態 + '：找到 ' + 匹配清單.length + ' 個，成功 ' + 成功 + ' 個', 6000);
%>

使用方式：把這段腳本存成 Templates/批次歸類.md，在需要整理 Vault 時執行（命令面板 → Templater: Insert Template → 選擇這個模板）。第一次執行時保持 模擬模式: true，確認清單正確後改成 false 才實際移動。

腳本移動不可復原：Templater 腳本直接呼叫 Obsidian 的檔案 API，移動後無法用 Ctrl+Z 復原。建議搭配 Obsidian Git 插件（ch08 介紹過）做備份，並且首次使用一定要先跑模擬模式確認結果。

Auto Note Mover：零程式碼的自動歸類方案

如果覺得 Templater 腳本太複雜，Auto Note Mover 是另一個選擇。它是一個獨立插件，用圖形介面設定規則，完全不需要寫程式碼。

安裝路徑：設定 → 社群插件 → 搜尋 Auto Note Mover → 安裝並啟用。

設定規則的三個要素：

  • Folder（目標資料夾）：筆記要被移動到哪裡
  • Tag（標籤條件）：筆記帶有特定 #tag 時觸發移動
  • Title by regex（標題正則）：筆記名稱符合正則表達式時觸發移動
Auto Note Mover 規則範例：

規則 1：閱讀筆記自動歸類
  Folder:  Reading/Books
  Tag:     #閱讀筆記

規則 2：Daily Note 按年月歸類
  Folder:  Journal/2026-06
  Title regex:  ^2026-06   （以 "2026-06" 開頭的筆記）

規則 3：工作專案筆記歸類
  Folder:  Work/Active
  Tag:     #work/active

注意事項：
- 一個筆記命中多個規則時，以第一個規則為準
- 不想被移動的筆記，在 frontmatter 加上 disabled: true
- Vault 根目錄的筆記無法被規則觸發（需先移到子資料夾）

Auto Note Mover 預設是「自動觸發」——每次你儲存或建立筆記，它會即時檢查規則並自動移動。如果想先測試規則是否正確，可以改成「手動觸發」，用命令面板手動執行一次確認。

Templater 腳本 vs Auto Note Mover：兩者不互斥，各有適合的場景。Auto Note Mover 適合「持續性的自動分類規則」（例如所有 #工作 的筆記自動去 Work 資料夾）；Templater 腳本適合「一次性的批次整理任務」（例如把過去三個月的舊筆記一次整理好）。

Templater 常見問題

語法執行沒效果，模板貼進去還是原始文字

最常見的原因：你用的是「複製貼上」，不是透過 Templater 命令插入模板。Templater 語法只有在透過命令面板的「Templater: Insert Template」，或者新建筆記時自動套用，才會被執行。直接複製模板內容貼到筆記，語法不會被解析。

tp.date.now() 顯示的是英文星期

Templater 的日期格式使用 Moment.js，語言跟隨 Obsidian 的語系設定。如果顯示英文但你想要中文，在 Obsidian 設定裡把介面語言改成繁體中文（或簡體中文），dddd 就會輸出「星期五」而不是「Friday」。

腳本執行後彈出「Failed to run Templater」錯誤

腳本模式（<%* ... %>）裡的語法錯誤不會有詳細的錯誤訊息。開啟 Obsidian 的開發者工具（Ctrl+Shift+I），切到 Console 頁籤，重新執行腳本，就能看到具體的 JavaScript 錯誤行號。

小結

Templater 讓模板從「靜態文字」進化成「動態腳本引擎」。本章涵蓋了它的完整能力：

  • 四大 tp.* 模組：tp.date 處理時間計算、tp.file 讀取檔案資訊（含游標定位）、tp.system 實現互動式 prompt/suggester、tp.user 掛載可重用的自訂函數。
  • 常用模板範例：每日筆記、會議記錄、讀書筆記、專案啟動——每個模板都示範了如何用 frontmatter 欄位為 Dataview 提供查詢資料。
  • Folder Templates：不同資料夾各自對應不同模板，新建筆記時自動套用，零選擇摩擦。
  • Startup Template：Obsidian 啟動時自動執行腳本，例如自動建立今天的日記。
  • Templater + Dataview 組合：Templater 負責結構化的 metadata 輸入，Dataview 負責跨筆記聚合輸出。
  • 腳本模式（<%* ... %>）：完整 JavaScript 環境，可呼叫 Obsidian API 做批次操作。
  • Auto Note Mover：不需寫程式碼的圖形化規則設定，根據標籤或標題正則自動分類筆記。

Vault 的日常維護問題解決了，下一個挑戰是「附件的混亂」。隨著你在筆記裡越來越多地插入圖片和檔案，Vault 裡的附件資料夾會變得雜亂，甚至出現孤兒附件（筆記刪了，圖片還留著佔空間）。下一章我們介紹附件與圖片管理的最佳實踐，讓 Vault 保持整潔。
