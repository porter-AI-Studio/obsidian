第 7 章 · Part 2：核心功能：筆記、連結與關聯圖

日常筆記工作流：每日筆記與 LYT 系統

讓 Obsidian 成為你每天思考的起點，而不只是一個偶爾查閱的資料庫

知識結構有了，然後呢？

前幾章我們建立了 Obsidian 的核心結構：雙向連結讓筆記彼此相連，Graph View 讓知識可視化，Metadata 讓筆記可以被找到。但很多人用了一段時間後會發現一個新問題：

知識庫整理得很漂亮，但每天早上打開 Obsidian，我還是不知道要從哪裡開始。

這個問題的解答，是 每日筆記（Daily Notes）。它是 Obsidian 為數不多的「有時間軸」的功能——每天一則，按日期命名，讓你有一個固定的思考起點。搭配 LYT（Linking Your Thinking） 這套知識管理框架，日常輸入和長期知識積累就能連成一條可以流動的管道。

Daily Notes：每天的思考收件匣

Daily Notes 是 Obsidian 的核心插件之一，開啟方式：設定 → Core Plugins → Daily Notes → 啟用。啟用後，每天可以用快捷鍵 Alt+D 快速建立今天的筆記，或在左側工具欄點擊日曆圖示。

Daily Note 最實用的定位，是充當你每天的知識收件匣（Inbox）：

  • 今天閱讀文章的摘要與感想
  • 會議紀錄與討論摘要
  • 突然冒出來的想法（Fleeting Notes）
  • 今天的待辦清單
  • 當天的情緒或觀察（若有日記習慣）

這些東西不需要分類，不需要想「該放哪個資料夾」——先統統倒進今天的 Daily Note，之後再整理。這個「先收後整理」的觀念，是所有知識管理系統的共同核心。

Daily Note 模板設計

搭配模板插件（Templater 或 Core Templates），每天的 Daily Note 可以自動填入固定結構： 

---
date: 2026-06-20
week: W25
---

## 今日重點
- [ ]

## 會議筆記
<!-- 今天的會議記錄放這裡，完成後連結到對應的人物或專案筆記 -->

## 閱讀與學習
<!-- 今天看到的文章、影片、書籍摘要 -->

## 想法速記
<!-- 隨手記下的想法，之後整理成知識卡片 -->

## 今日回顧
<!-- 一天結束前花 5 分鐘填寫 -->

建議資料夾結構：將所有 Daily Notes 統一存放在 Calendar/Journal/ 資料夾，按年份建子資料夾（如 Calendar/Journal/2026/）。在 Daily Notes 設定裡指定「新筆記位置」即可自動歸位。

LYT：給你的知識庫一個骨架

Daily Notes 解決了「每天從哪裡開始」的問題，但它本身是線性的——一天一則，按時間排列。如果每天的想法只停留在 Daily Note 裡，就跟寫日記差不多，無法積累成可以被重複利用的知識。

這時候需要一個長期知識架構，把 Daily Notes 的輸入轉化為有結構的知識。LYT（Linking Your Thinking，連結你的思考） 就是目前 Obsidian 社群最廣泛使用的框架。它由 Nick Milo 在 2020 年開發，免費版的入門套件已被下載超過 70,000 次。

LYT 的核心信念只有一句話：

不要用分類整理筆記，用連結。

核心概念一：MOC（Maps of Content，內容地圖）

MOC 是 LYT 最重要的發明。它是一則專門用來連結其他筆記的索引筆記——裡面放的是指向其他筆記的連結，按照你的思路排列。

它不是資料夾，不是標籤，而是一張你自己畫的主題地圖。舉個例子：

# AI MOC

## 核心概念
- [[Agentic Coding]]
- [[MCP]]
- [[Claude Skills]]

## 工具與實踐
- [[Claude Code]]
- [[AI Agent]]

## 我的洞察
- [[MCP 與 Skills 是廚房與食譜的關係]]
- [[AI 工具的普及是分發問題]]

## 近期資訊
- [[Anthropic 收購 Bun]]（2025-12）

MOC 和資料夾最大的差別：一則筆記可以同時出現在多個 MOC 裡。[[Claude Code]] 既出現在 AI MOC，也出現在 PKM MOC，因為它跨越了兩個主題。資料夾做不到這件事。

什麼時候建 MOC？Nick Milo 的建議是：當同一個主題累積到 5~10 則筆記，你開始感覺「有點亂」的時候。這個「有點亂」是一個訊號，代表這個主題已經值得有一張地圖了。

核心概念二：ACE 頂層架構

MOC 管個別主題，但整個 Vault 的頂層結構呢？LYT 用 ACE 三個資料夾解決這個問題： 

Vault/
├── Atlas/        ← 我「知道」什麼（知識）
│   ├── Notes/    ← 知識卡片
│   ├── Maps/     ← MOC 索引
│   └── Sources/  ← 書、文章、剪藏
├── Calendar/     ← 我「經歷」了什麼（時間）
│   └── Journal/  ← Daily Notes
└── Efforts/      ← 我「在做」什麼（行動）
    ├── Areas/    ← 持續進行的領域
    ├── Projects/ ← 有明確終點的專案
    └── Works/    ← 已完成的產出

ACE 的設計哲學不只是整理檔案，而是讓你在不同資料夾裡切換不同的思考模式：打開 Atlas 是學習模式，打開 Calendar 是反思模式，打開 Efforts 是執行模式。很多人的問題是把所有東西混在一起——學習筆記和待辦清單放同一個地方，兩邊都做不好。ACE 用物理空間幫你切換心智狀態。

Daily Notes 的位置：在 ACE 架構裡，Daily Notes 放在 Calendar/Journal/。它屬於「時間軸」的空間——記錄你「經歷了什麼」，而不是「知道什麼」（Atlas）或「在做什麼」（Efforts）。

核心概念三：五種筆記類型

LYT 把知識卡片分成五種類型，幫你打破「所有筆記都長一個樣」的盲點：

  • Things：這是什麼？（概念定義、工具說明）
  • Statements：我怎麼想？（你的洞察、觀點、原則）
  • Questions：我好奇什麼？（待探索的問題）
  • Quotes：別人怎麼說？（值得記下的引言）
  • People：這個人是誰？（人物筆記）

大多數人只寫 Things——「X 是什麼」「Y 怎麼用」。但真正讓知識系統產生價值的是 Statements——你自己的想法。一個月後你回來看自己當時的洞察，那個筆記才有真正的意義。

Daily Notes 如何融入 LYT

有了 ACE 架構和 MOC 的概念，Daily Notes 的角色就更清楚了：它是輸入門戶，而 Atlas 的知識卡片是長期儲存。兩者之間的橋樑，是定期的「整理動作」。

會議筆記的連結策略

日常最常遇到的場景是會議記錄。一個實用的做法是：把會議記錄放在當天的 Daily Note 裡，然後用 [[wikilink]] 連結到相關的人物筆記或專案筆記。例如： 

## 會議筆記 - 2026/06/20

### 與 [[Brian]] 的一對一會議
- 討論 [[官網改版專案]] 的下一步
- #discussion-topic 需要和 [[Maria]] 確認 SEO 策略

→ 行動項目：下週前提供 [[竹蜻蜓設計稿]] 初版

這樣做的效果：Brian 的人物筆記的反向連結面板會自動顯示你和他的所有討論；官網改版專案筆記也能追蹤到所有相關的會議記錄。不需要手動整理，連結讓資訊自動歸位。

從 Daily Note 到知識卡片的流動

每週或每隔幾天，翻閱最近的 Daily Notes，把其中有價值的想法「升格」為知識卡片：

  • 在想法速記裡看到一個反覆出現的洞察 → 建立一則 Statement 筆記
  • 某篇文章的摘要值得長期保留 → 建立一則 Things 筆記並連結到對應 MOC
  • 某個待跟進的話題已有足夠筆記 → 建立一張 MOC 把散落的筆記整合起來

Daily Notes 不是最終目的地，而是一個緩衝區——讓你可以先不加判斷地輸入，之後再決定哪些值得升格進入長期知識庫。

不要讓 Daily Notes 堆積太久：如果超過兩週沒有整理，Daily Notes 就會變成另一個混亂的 Inbox。建議每週固定花 20~30 分鐘做「週回顧」——掃描本週的 Daily Notes，把值得保留的內容升格，把完成的待辦事項標記，把沒用的草稿刪除。

兩種使用模式

LYT 看起來架構複雜，但實際上你可以選擇適合自己的深度：

輕量模式：Daily Note 作 Inbox

只用 Daily Notes，不建 ACE 架構。每天記錄，每週整理，把有價值的內容用 [[wikilink]] 連結到主題筆記。這個模式進入門檻低，適合剛開始用 Obsidian 的人。缺點是當筆記累積到幾百則之後，頂層導航會開始感覺混亂。

完整模式：ACE + MOC + Daily Notes

建立 Atlas/、Calendar/、Efforts/ 三個頂層資料夾，為每個主要主題建立 MOC，Daily Notes 放進 Calendar/Journal/。這個模式前期設定成本較高，但一旦結構穩定，知識積累的複利效應非常明顯。建議在 Vault 累積到 100~200 則筆記後，再考慮導入完整架構。

LYT 和 PARA 的差異：PARA（Tiago Forte 的框架）用資料夾按專案分類，適合以行動為中心的人；LYT 用連結和 MOC 建立知識網絡，適合以學習和思考為中心的人。兩者不是非此即彼，許多人會把 Efforts 資料夾的結構借鑒自 PARA 的專案管理邏輯。

Periodic Notes：從每日延伸到週、月、年

Daily Notes 解決的是每天的輸入問題，但真正的知識積累需要更長的週期回顧。Periodic Notes 插件（社群插件，需另行安裝）把 Daily Notes 的概念擴展到週記（Weekly）、月記（Monthly）和年記（Yearly），讓你的反思週期形成完整的閉環。

五步驟週回顧 SOP

週回顧是整個系統的關鍵齒輪——沒有它，Daily Notes 只會越堆越多而不產生複利。以下是一個可以在 20~30 分鐘內完成的標準流程：

  1. 掃描本週 Daily Notes：快速瀏覽，標記值得升格的想法（可用高亮或加標籤 #review）
  2. 升格知識卡片：把標記過的 fleeting notes 整理成獨立的 Atlas 筆記，補充脈絡和連結
  3. 更新 MOC：把升格後的卡片加進對應的 MOC，或決定是否需要建立新 MOC
  4. 回顧 Efforts：檢查本週各專案的進度，更新 Kanban 或待辦清單狀態
  5. 寫下洞察與下週重點：一句話總結本週最大的領悟，以及下週三個最重要的行動項目

小結

Daily Notes 是 Obsidian 日常使用的起點：每天的想法、會議、閱讀統一倒進這個收件匣，不用擔心分類；再透過 [[wikilink]] 把當下的記錄連接到長期知識——這樣知識庫才能真正「活著」，而不是堆放資料的檔案夾。

LYT 的 MOC 提供了一個在連結之上的地圖層，讓你在知識網絡裡不會迷路。ACE 的三個空間（知識 / 時間 / 行動）讓你的 Vault 從一開始就有清晰的頂層結構，不需要反覆重組。

Periodic Notes 把反思的週期延伸到週、月、年——Daily Notes 是每天的輸入，Weekly Review 是每週的消化，Monthly Review 是每月的精煉。每個週期都有明確的「整理動作」，讓知識不只是輸入，而是真正沉澱成複利。
