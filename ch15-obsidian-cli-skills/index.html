第 15 章 · Part 5：AI 整合：打造 AI 驅動的知識庫

Obsidian CLI 與 AI Skills：讓 AI 自動寫筆記

Obsidian CLI 是最後一片拼圖——讓 AI 從「讀取檔案」升級為「操作知識庫」

為什麼 Obsidian CLI 是重磅更新？

上一章我們建立了 Claude Code 讀寫 Obsidian Vault 的基礎架構。但你可能注意到一個限制： Claude Code 讀寫的本質是檔案系統操作——它讀取 Markdown 文字、修改內容、寫回檔案， 卻對 Obsidian 的「內部世界」一無所知：雙向連結的圖譜關係、Canvas 畫板、Bases 資料庫、插件狀態。

Obsidian CLI 改變了這一切。它是 Obsidian 官方推出的命令列介面， 讓 AI 不再只是「外部讀寫者」，而是能透過官方渠道觸發 Obsidian 的內部機制—— 創建雙向連結、更新圖譜、呼叫插件、操作 Canvas，就像你手動在 Obsidian 介面裡操作一樣， 但全由 AI 自動完成。

命令列對 AI 來說是最高效的操作方式，比逐行讀取 Markdown 節省大量 token。 當 CLI 與 Skills 技能包結合，AI 就擁有了完整的「知識庫操作能力」。

CLI vs 直接讀取 Markdown：關鍵差異

在設定之前，先釐清一個常見混淆：市面上有幾個工具名稱相似，但性質完全不同。

工具 操作方式 能觸發 Obsidian 內部機制？ Token 消耗
Obsidian CLI（官方） 透過官方 CLI 指令操作 ✅ 是 低
直接讀寫 .md 檔案 Claude Code 讀取/寫入檔案 ❌ 否 中
notesmd-cli（舊版開源） 操作 Markdown 檔案系統 ❌ 否 高

避坑提醒：OpenClaw（大龍蝦）官方 GitHub 倉庫中有一個 obsidian skill，但它實際上使用的是 2023 年的開源項目（現已改名 notesmd-cli），並非 Obsidian 官方 CLI。這個工具只做文件 I/O，不觸發 Obsidian 內部機制，且 token 消耗更高。若你使用 OpenClaw，請到 ClawHub 官方市場安裝正確的 Obsidian CLI skill。

三步完成環境建置

整個設定流程分三個準備工作，大約 15 分鐘可以完成。

# 步驟一：升級 Obsidian 到最新版本
# 設定 → 關於 → 開啟「命令列界面」功能
# 重啟 Obsidian 後，CLI 功能啟用

# 步驟二：安裝 Claudian 插件（GitHub 手動安裝）
# 1. 前往 GitHub 搜尋 "claudian obsidian"
# 2. 下載 Release 中三個核心檔案：

# 4. 將三個檔案放入後重啟 Obsidian

# 1. GitHub 搜尋 "kepano obsidian-skills"
# 2. 下載壓縮包並解壓
# 3. 將 skills 資料夾中的 .md 檔案複製到：

步驟一細節：開啟 Obsidian CLI

Obsidian 的 CLI 功能需要 1.12 以上版本，預設是關閉的。 進入設定 → 關於，拉到最下方會看到「命令列界面」選項，點擊啟用後重啟即可。 啟用後，AI 工具就能透過 CLI 指令與 Obsidian 通訊。

版本號查證（2026-09 查證）：官方 Obsidian CLI 於 2026-02-10 先以 Catalyst 搶先體驗形式推出，2026-02-27 隨 1.12.4 版正式對所有使用者開放，需求版本是 1.12+，並非 1.8.x——這是本章原先誤植的版本號，請依此更正安裝前提。

步驟二細節：Claudian 插件

Claudian 是目前最主流的 Obsidian × Claude Code 整合插件， 可以把 Claude Code 的對話界面直接嵌入 Obsidian 側邊欄， 不需要切換到終端機視窗。

安裝方式更新（2026-09 查證）：Claudian 已從 beta 轉正，正式上架 Obsidian 官方社群插件市場，下載量已超過 180 萬次——現在可以直接在設定 → 社群插件 → 瀏覽搜尋「Claudian」一鍵安裝，不再需要手動下載 GitHub Release 檔案。手動安裝法（下載 main.js / manifest.json / styles.css 放入 .obsidian/plugins/claudian/）仍然可行，適合想用開發版或搶先版本的使用者。

另一個選擇是 obsidian-agent-client，支援 Claude Code、Codex、Gemini CLI、OpenCode 等多種 AI 工具， 彈性更高，適合同時使用多個 AI 工具的使用者。兩個插件選一個安裝即可。

步驟三細節：Skills 技能包

Obsidian CEO（kepano）親自編寫了 5 個官方 Skill，放在 GitHub 的 kepano/obsidian-skills 倉庫。 這些 Skill 是針對 Obsidian 量身設計的操作規範，讓 AI 了解如何正確寫入雙向連結、建立 Canvas、操作 Bases 資料庫。 安裝方式是把 skill 檔案放到 Vault 的 .claude/skills/ 資料夾。

5 個核心 Skill 完整解析

以下是 Obsidian 使用者最值得安裝的 Skill 清單，按優先順序排列：

1. Defuddle Skill — 網頁與影片剪藏（必裝）

Defuddle 是 Obsidian 官方 Web Clipper 的底層引擎，同樣由 kepano 開發。 作為 Skill 使用時，你可以直接在對話框貼上網頁連結，AI 就會呼叫 defuddle 把頁面轉成結構化 Markdown。 最近的更新還加入了YouTube 字幕提取功能，輸入影片連結就能一鍵轉成筆記， 且使用 YouTube 官方 API，比 yt-dlp 更穩定，不需要配置 cookie。 

# 安裝 defuddle 命令列工具
npm install -g defuddle

# 在 Claudian 對話框中直接發送網頁連結
# Claude 會呼叫 defuddle skill 自動剪藏
# 範例：「請把這篇文章存成讀書筆記」
# https://example.com/article

# YouTube 影片也支援（提取字幕轉 Markdown）
# https://www.youtube.com/watch?v=xxxx

2. Obsidian CLI Skill — 知識庫原生操作（必裝）

這是整合 Obsidian CLI 的核心 Skill，讓 AI 能夠透過 CLI 指令操作你的知識庫， 而不是直接讀寫 Markdown 檔案。有了這個 Skill，AI 能清楚理解你整個知識庫的架構和 metadata， 為後續的 Bases、Canvas 操作提供基礎。

3. Bases Skill — AI 生成複雜資料庫視圖（必裝）

Obsidian 的 Bases 功能讓你用 YAML 定義資料庫視圖。這個 Skill 教 AI 如何正確撰寫 .base 格式， 搭配 CLI Skill 一起使用效果最佳——AI 先透過 CLI 理解知識庫結構， 再用 Bases Skill 生成複雜的看板、追蹤特定筆記群組。 這是 Obsidian 生態系中目前獨一無二的 Skill，沒有替代品。

4. Markdown Skill — 格式規範與個人化（建議擴充）

這個 Skill 給 AI 制定了一套 Obsidian 筆記的寫作 SOP：什麼時候用雙向連結、 如何使用 Callout 格式、frontmatter 的欄位規範。 雖然 AI 訓練資料中包含 Obsidian 語法，但 AI 有「向通用標準坍縮」的傾向， 可能會輸出標準 Markdown 而不是 Obsidian 專屬語法。

建議直接在這個 Skill 的內容中加入你的個人格式偏好，例如「不使用一級標題」、 「嵌套列表最多兩層」等。這個 Skill 全部是 Markdown 格式，不需要任何程式基礎就能修改。

5. Tutor Skill — PDF / 文件自動轉成知識庫（重點推薦）

這是最令人驚喜的 Skill：把你想學習的 PDF、技術文件、GitHub 專案丟進去， AI 會自動生成一個完整的 Obsidian 知識庫，包含雙向連結筆記、MOC 內容地圖、結構化標籤， 甚至還有針對性的測驗題。 

# Tutor Skill 使用流程
# 1. 建立學習目錄結構
mkdir my-study-project
cd my-study-project
mkdir resources StudyVault

# 2. 將學習資料（PDF / 文件）放入 resources 資料夾

# 3. 在 Claudian 或 AI Agent 對話中執行
/tutor-setup

# 4. 等待 AI 自動生成完整 Obsidian 知識庫
#    包含：雙向連結筆記 / MOC 內容地圖 / 結構化標籤

# 5. 用 Obsidian 開啟 StudyVault 資料夾查看結果
# 6. 執行測驗
/tutor

Tutor vs Scholar：同類型還有一個 Scholar Skill，適合學術科研，具備三級閱讀體系和長週期任務編排，但極度消耗 token，深度依賴 OpenClaw。日常學習建議優先使用 Tutor Skill，學術研究才考慮 Scholar。

畫圖類 Skill：Axton 的三個替代方案

kepano 官方的 json-canvas Skill 在佈局和排版上效果有限。 博主 Axton（回到 Axton）重構的三個畫圖 Skill 效果更佳，節點大小計算更準確：

  • json-canvas（Axton 重構版）：思維導圖，支援分組結構化展示
  • Mermaid Skill：流程圖、序列圖，成功率高，幾乎不需手動調整
  • Excalidraw Skill：手繪風格圖表，適合頭腦風暴，Obsidian 插件市場下載量第一

3 個實戰場景示範

場景一：智能讀書筆記

在 Claudian 對話框輸入：「請幫我創建一篇《納瓦爾寶典》的讀書筆記，使用讀書筆記模板」。 Claude 不會只是套用模板了事，它會主動搜尋你 Vault 裡的其他讀書筆記作為參考， 模仿筆記的風格和結構來生成新筆記，並放到正確的資料夾位置。 這種「找參考 → 模仿 → 生成」的行為，展示了 AI 在 Obsidian 裡的真實思考邏輯。

場景二：批次整理收藏文件

「收藏一時爽，整理火葬場」是每個知識工作者的痛。 你可以把一批零散的收藏文章丟進 Vault，然後對 Claudian 說：「幫我整理這批 Python 相關的文件」。 AI 會分析每篇文件的內容、刪除重複收藏、生成條理清晰的歸類目錄， 整個過程不需要你逐篇閱讀。

場景三：Canvas 知識圖譜

對 Claudian 輸入 /canvas 請將這篇深度文章的核心概念畫成思維導圖， AI 就會呼叫 Canvas Skill，自動生成結構化的 Canvas 畫板。 搭配 CLI Skill，AI 能理解你的整體知識網路， 用 1 分鐘找出所有同時涉及「AI」和「知識管理」的筆記，並生成 Canvas 知識圖譜。

進階技巧

YOLO 模式 vs 確認模式

Claudian 有一個 YOLO（You Only Live Once）開關。 開啟時，AI 全程自動執行，包括修改和刪除檔案，不會逐步詢問你。 適合你完全信任 AI 判斷的批次整理任務。 關閉時，每個操作執行前都會先詢問確認——做重要筆記的修改時建議關閉。

Plan 模式（Shift + Tab）

按 Shift + Tab 切換到 Plan 模式，AI 會先列出完整的執行方案和步驟， 不會有任何實際操作。你可以與它討論、修改計劃，確認架構後再讓它開始執行。 適合創建複雜工作流、架構調整等高風險任務。

多模型配置

Claudian 允許為 Obsidian 單獨配置不同的 AI 模型，與全局的 Claude Code 設定分開。 例如：平時寫程式用擅長編程的模型，在 Obsidian 做文字整理則換成更適合語言任務的模型（如 DeepSeek）。 進入設定 → 環境即可獨立配置。

Git 備份：給自己留後悔藥

AI 大修文件前，強烈建議先用 Obsidian Git 插件備份一次 Vault 狀態。 如果 AI 改完後你覺得原版更好，一鍵還原上一個版本即可， 不需要讓 AI 耗費大量 token 嘗試把內容「改回去」。

本章小結

Obsidian CLI 開啟了 AI 與知識庫整合的新維度。 透過 Claudian 插件把 Claude Code 嵌入 Obsidian，再搭配 Skills 技能包， 你的知識庫就從「被 AI 讀取的文件集合」升級成「AI 可以操作的智能系統」。

核心 Skill 優先順序：Defuddle（剪藏）→ CLI（原生操作）→ Bases（資料庫）→ Markdown（格式規範）→ Tutor（深度學習）。 五個 Skill 各司其職，覆蓋從資訊收集到知識生產的完整流程。

下一章我們進入更底層的知識架構設計：LLM Wiki——受 Karpathy 啟發的自動進化知識庫， 讓 AI 不只是幫你整理筆記，而是讓你的整個知識體系隨著時間自動生長。

進階實戰：Local REST API 直接操作 Vault

除了透過 Claudian 插件的對話介面，你還可以讓 PowerShell 腳本或 Claude Code 直接透過 Local REST API 操作 Obsidian——不需要打開 Obsidian 介面， 只需 Obsidian 在後台執行即可。這是批次處理與排程自動化的基礎。

安裝與設定 Local REST API 插件

Local REST API 是社群插件（作者：CoddingWithJairo），讓 Obsidian 在本機啟動一個 HTTP 伺服器，預設監聽 Port 27123。任何能發出 HTTP 請求的程式都可以透過它讀寫 Vault。 

# 安裝 obsidian-local-rest-api 插件
# 1. Obsidian → 設定 → 社群插件 → 搜尋 "Local REST API"
# 2. 安裝並啟用 "Local REST API" 插件（CoddingWithJairo 維護）
# 3. 插件設定中複製 API Key，預設 Port 為 27123

# 建立 .env 檔案（放在 Vault 根目錄或專案目錄）
# .env
OBSIDIAN_API_KEY=你的-API-Key-貼這裡
OBSIDIAN_PORT=27123
OBSIDIAN_HOST=127.0.0.1

# 測試 API 連線（PowerShell）
$headers = @{ "Authorization" = "Bearer $env:OBSIDIAN_API_KEY" }
Invoke-RestMethod `
  -Uri "http://127.0.0.1:27123/vault/" `
  -Headers $headers `
  -Method GET

安全提醒：API Key 請務必存入 .env 或 Windows 環境變數，不要寫死在腳本裡。若在 Git 版控的專案中，記得把 .env 加入 .gitignore。

PowerShell 函式庫：讀取、建立、搜尋

以下封裝三個最常用的 REST 操作，建議存成 ObsidianAPI.ps1 後以 . .\ObsidianAPI.ps1 引入。 

# PowerShell 函式庫：封裝 Obsidian Local REST API
function Get-ObsidianNote {
    param([string]$Path)
    $headers = @{ "Authorization" = "Bearer $env:OBSIDIAN_API_KEY" }
    $encoded = [Uri]::EscapeDataString($Path)
    return Invoke-RestMethod `
        -Uri "http://127.0.0.1:27123/vault/$encoded" `
        -Headers $headers -Method GET
}

function New-ObsidianNote {
    param([string]$Path, [string]$Content)
    $headers = @{
        "Authorization" = "Bearer $env:OBSIDIAN_API_KEY"
        "Content-Type"  = "text/markdown"
    }
    $encoded = [Uri]::EscapeDataString($Path)
    Invoke-RestMethod `
        -Uri "http://127.0.0.1:27123/vault/$encoded" `
        -Headers $headers -Method PUT -Body $Content
}

function Search-ObsidianVault {
    param([string]$Query)
    $headers = @{ "Authorization" = "Bearer $env:OBSIDIAN_API_KEY" }
    return Invoke-RestMethod `
        -Uri "http://127.0.0.1:27123/search/simple/?query=$Query" `
        -Headers $headers -Method GET
}

# 使用範例
$env:OBSIDIAN_API_KEY = "your-api-key"
$note = Get-ObsidianNote -Path "工作日誌/2026-07-02.md"
Search-ObsidianVault -Query "Claude Code"

讓 Claude Code 知道如何操作 API

把 API 端點資訊寫進 Vault 根目錄的 CLAUDE.md， Claude Code 就能在對話中直接呼叫 REST API，不需要每次手動貼端點文件。 

# CLAUDE.md 設定：讓 Claude Code 知道如何操作 Vault API
# 放在 Vault 根目錄的 CLAUDE.md 中

## Obsidian Local REST API
- Base URL: http://127.0.0.1:27123
- API Key: 從環境變數 OBSIDIAN_API_KEY 讀取
- 搜尋端點: GET /search/simple/?query=<關鍵字>
- 讀取端點: GET /vault/<path>
- 寫入端點: PUT /vault/<path>  (body: text/markdown)
- 刪除端點: DELETE /vault/<path>

## 操作規則
1. 建立筆記前先呼叫 Search-ObsidianVault 確認不重複
2. frontmatter 必須包含 title / created / tags
3. 標籤使用 kebab-case，不使用空格
4. 雙向連結使用 [[筆記名稱]] 格式，不加副檔名

MCP Server 替代方案：若你使用 Claude Desktop（非 Claude Code CLI），可以安裝 github.com/MarkusPfundstein/mcp-obsidian 作為 MCP Server。它底層同樣呼叫 Local REST API，但透過 MCP 協議讓 Claude Desktop 直接當作工具呼叫，設定更簡便，適合不熟悉 PowerShell 的使用者。

批次處理：大規模整理筆記

批次處理是 PowerShell + Local REST API 最強大的應用場景。 你不需要逐一手動打開每篇筆記，而是讓腳本在背景完成所有操作。

批次加 Frontmatter

從其他工具（Notion、Apple Notes、Bear）匯入的筆記通常沒有 frontmatter。 以下腳本會掃描整個 Vault，為沒有 frontmatter 的 .md 檔案自動補上標準屬性。 

# 批次為沒有 frontmatter 的筆記加上標準屬性
# 執行前先在 Obsidian 開啟 Git 插件並 commit 一次（留後悔藥）

$vaultPath = "C:Obsidianault"
$today     = Get-Date -Format "yyyy-MM-dd"

Get-ChildItem -Path $vaultPath -Filter "*.md" -Recurse | ForEach-Object {
    $content = Get-Content $_.FullName -Raw -Encoding UTF8

    # 跳過已有 frontmatter 的檔案
    if ($content -match "^---") { return }

    # 從檔名推斷標題（去除副檔名、底線換空格）
    $title = $_.BaseName -replace "_", " "

    $frontmatter = @"
---
title: $title
created: $today
tags: []
---

"@
    $newContent = $frontmatter + $content
    Set-Content -Path $_.FullName -Value $newContent -Encoding UTF8
    Write-Host "已更新：$($_.Name)"
}

執行前備份：批次修改前，務必先在 Obsidian Git 插件執行一次 commit，或手動備份 Vault 目錄。萬一腳本有 bug，才能用 git checkout 一鍵還原。

批次重命名：snake_case → kebab-case

從 Notion 或 Evernote 匯出的檔名往往帶有底線或空格。 以下腳本統一改為 kebab-case（連字符命名），方便後續 wikilink 和搜尋。 

# 批次重命名：將底線命名法改為連字符命名法
# 適用於從其他工具（Notion / Apple Notes）匯入後的整理

$vaultPath = "C:Obsidianault收件箱"

Get-ChildItem -Path $vaultPath -Filter "*.md" | ForEach-Object {
    $oldName = $_.Name
    # snake_case → kebab-case，空格也轉連字符
    $newName = $oldName `
        -replace " ", "-" `
        -replace "_", "-" `
        -replace "--+", "-"   # 合併多個連字符

    if ($oldName -ne $newName) {
        $newPath = Join-Path $_.DirectoryName $newName
        Rename-Item -Path $_.FullName -NewName $newName
        Write-Host "$oldName → $newName"
    }
}

自動化觸發：排程代理與 Webhook

手動執行腳本只是第一步，真正的「知識庫自動運作」需要讓腳本在特定時機自動觸發。 搭配 obsidian-second-brain skill（基於 Karpathy LLM Wiki 概念）， 你可以設定四種排程代理，讓知識庫在你睡覺時自動進化。 

# obsidian-second-brain 排程代理設定
# 安裝：npm install -g obsidian-second-brain（或從 ClawHub 安裝 skill）

# 夜間自動化（每天 23:00 執行）
# 在 Windows 工作排程器 或 cron（WSL）中設定：

# 1. 夜間總結（nightly wrap-up）
#    讀取當日所有新增筆記 → 生成摘要 → 更新 MOC
claude --print "/nightly-wrapup" --vault "C:Obsidianault"

# 2. 矛盾掃描（每週一執行）
#    掃描知識庫中互相矛盾的陳述 → 建立待確認清單
claude --print "/contradiction-scan" --vault "C:Obsidianault"

# 3. Vault 健康檢查（每月第一天）
#    找出孤兒筆記、斷裂連結、空標籤 → 生成健康報告
claude --print "/vault-health-check" --vault "C:Obsidianault"

# Windows 工作排程器快速設定（PowerShell）
$action  = New-ScheduledTaskAction `
    -Execute "claude" `
    -Argument '--print "/nightly-wrapup"'
$trigger = New-ScheduledTaskTrigger -Daily -At "23:00"
Register-ScheduledTask -TaskName "ObsidianNightlyWrapup" `
    -Action $action -Trigger $trigger -RunLevel Highest
排程代理 執行時機 功能說明 Token 消耗
Nightly Wrap-up 每天 23:00 整理當日新增筆記、更新 MOC、生成日誌摘要 低
Contradiction Scan 每週一 找出 Vault 中互相矛盾的陳述，建立待確認清單 中
Weekly Review 每週日 本週學習摘要、連結補強、孤兒筆記歸類 中
Vault Health Check 每月第一天 斷裂連結、空標籤、重複筆記全面掃描 高

Windows 工作排程器設定：上方程式碼已包含用 PowerShell 建立排程任務的指令。執行後打開「工作排程器」即可看到 ObsidianNightlyWrapup 任務，可在介面中調整時間或停用。

obsidian-second-brain：45 個自動化指令

obsidian-second-brain（作者：Eugeniu Ghelbur）是目前功能最完整的 跨 LLM CLI 整合 Skill，支援 Claude Code、Codex、Gemini CLI、OpenCode 四個 AI 工具。 它以 Karpathy 的 LLM Wiki 為基礎，但做了一個關鍵升級： 不只是追加新資訊，而是重寫現有頁面、調和矛盾、自動生成跨來源的綜合筆記。

45 個指令中，最值得立即試用的幾個：

  • /challenge：AI 主動質疑你筆記中的假設，找出邏輯漏洞
  • /visualize：把概念筆記轉成 Canvas 思維導圖
  • /obsidian-architect：掃描程式碼庫，自動寫入架構筆記到 Vault
  • /ingest-video：YouTube 影片摘要直接存入 Vault（支援語音轉錄）
  • /nightly-wrapup：夜間自動整理，讓 Vault 每天早上都是最新狀態

multi-LLM 策略：obsidian-second-brain 支援在同一個 Vault 同時接入多個 AI CLI。建議的分工方式是：日常寫作用 Claude Code（語言品質最高）、程式碼分析用 Codex、成本敏感的批次操作用 Gemini CLI（每日免費額度最多）。在 CLAUDE.md 中定義每個 AI 的職責分工，避免重疊和衝突。
