附件與圖片管理：讓 Vault 保持整潔

從散落一地到井然有序——圖片跟著筆記走的完整方案

剛開始使用 Obsidian 時，圖片管理看起來不是問題：截圖貼上，立刻出現在筆記裡，省事。 但三個月後，當你的 attachments/ 資料夾裡堆了兩百張不知屬於哪篇筆記的截圖， 找一張圖要翻半天，你就知道問題在哪了。

Obsidian 的附件管理有個根本設計取捨：它把所有附件都存在本地（這是優點）， 但預設不限制存放位置（這是隱患）。本章的目標就是把這個隱患消除，讓圖片自動跟著筆記走。

問題根源：預設設定的四個痛點

Obsidian 的原廠附件行為會造成以下困擾：

  • 所有附件堆在根目錄：attachments/ 變成無差別垃圾桶
  • 隨機命名：截圖自動命名 Pasted image 20250329.png，毫無意義
  • 刪了筆記，圖片還在：孤兒圖片佔用空間無法自動清除
  • 笔記移動後引用斷掉：手動移動附件會讓筆記裡的圖片連結失效

四種附件組織策略

根據使用習慣，常見的組織方式有四種，各有取捨：

策略 結構範例 優點 缺點
單一目錄（預設） /attachments/圖片.png 零設定 附件多後極度混亂
按日期分類 /attachments/2025-03/筆記名/圖.png 時間軸清晰 找附件需記得日期
按檔案大小 /attachments/1-5MB/圖.png 方便識別需壓縮的圖 與筆記內容無關聯
按筆記名分類（推薦） /assets/專案計劃/圖1.png 附件與筆記綁定，搬移不斷線 需插件輔助自動化

絕大多數重度使用者最終都會選擇「按筆記名分類」——每篇筆記旁邊建立同名子目錄， 附件完全跟著筆記走，不管你把筆記搬到哪個資料夾，附件關係永遠正確。

原生設定：先做這一步

不安裝任何插件，Obsidian 原生就支援基本的附件位置設定：

# Obsidian 原生設定路徑
設定 → 檔案與連結 → 新附件的預設位置

選項一：Vault 根目錄（預設，不建議）
選項二：指定資料夾 → attachments/
選項三：與目前筆記相同的資料夾
選項四：目前資料夾的子資料夾 → assets/（推薦）

# 推薦設定：每篇筆記旁邊建立 assets/ 子目錄
新附件位置：目前資料夾的子資料夾
子資料夾名稱：assets

「目前資料夾的子資料夾 → assets」是最保守的起點—— 不需要插件，圖片就會存在筆記旁邊的 assets/ 目錄，已比預設好很多。 但它的缺點是：筆記重新命名或移動後，不會自動更新附件路徑。 要解決這個問題，需要下一節的插件。

插件一：Custom Attachment Location（核心必裝）

這是附件管理最關鍵的插件，解決了原生設定最大的痛點： 附件路徑與筆記生命週期完全同步。 

# Custom Attachment Location 插件設定（推薦方案）
# 安裝：設定 → 社群插件 → 搜尋 custom-attachment-location

附件路徑規則：./assets/${filename}/
# 效果：每篇筆記的附件存在同名子目錄
# 例：「專案計劃.md」的圖片 → assets/專案計劃/圖片1.png

# 啟用以下功能：
✅ 筆記重新命名時自動更新附件引用
✅ 筆記移動時自動遷移附件目錄
✅ 批次整理全庫現有附件（一鍵套用規則）

裝好後，整個 Vault 的附件管理邏輯就變成：

  • 貼圖時 → 自動存到 assets/筆記名/
  • 筆記改名 → 附件目錄自動跟著改名，筆記內連結自動更新
  • 筆記移動 → 附件跟著搬，連結不斷
  • 舊附件 → 執行「批次整理」，一鍵套用規則到全庫現有圖片

一鍵整理舊附件：安裝後在命令面板（Ctrl/Cmd + P）搜尋 Custom Attachment Location: Reorganize，即可將全庫既有附件按新規則批次搬移。 建議先備份 Vault 再執行。

插件二：Image Converter（圖片壓縮 + 編輯）

Image Converter 解決的是另一個痛點：截圖通常是 PNG，未壓縮的 PNG 動輒幾 MB， 累積幾百張後 Vault 體積暴增，同步速度也跟著變慢。

它的核心功能：

  • 自動壓縮：貼上圖片時自動轉成 WebP，體積縮小 70~80%
  • 格式統一：全庫圖片統一成 PNG / JPG / WebP，告別格式混雜
  • 自動重命名：以筆記名 + 序號命名（如 專案計劃-1.webp）
  • 右鍵複製：解決 Obsidian 圖片「貼得進去、複製不出去」的老問題
  • 滾輪縮放：按住 Ctrl + 滑鼠滾輪，直接在筆記內縮放圖片預覽大小

Image Converter vs Paste Image Rename： 如果你只裝一個，選 Image Converter——它涵蓋了 Paste Image Rename 的所有功能， 並額外增加壓縮與格式轉換。

插件三：Clear Unused Images（清除孤兒圖片）

刪除一篇筆記後，Obsidian 不會自動刪除它引用過的圖片——這些「孤兒圖片」靜靜佔用空間。 Clear Unused Images 插件可以掃描整個 Vault，找出沒有被任何筆記引用的圖片， 一鍵清除。

建議的使用節奏：每個月執行一次，搭配清理無用筆記一起做。

三插件併用的已知風險（2026-09 查證）：Obsidian 官方論壇在 2025 年底有使用者回報， 同時併用 Custom Attachment Location、Image Converter、Clear Unused Images 三個插件時， 偶爾會出現圖片誤刪或遺失的狀況——原因通常是三者對「附件路徑」的判斷時機沒有完全同步， Clear Unused Images 掃描時誤判某些圖片為孤兒檔。執行「清除孤兒圖片」前， 務必先用 Obsidian Git 或手動備份 Vault，並先用預覽/模擬模式確認清單再真正刪除。

統計 Vault 附件現況

整理前，先了解 Vault 的附件規模：

# macOS / Linux：統計 Vault 內的圖片數量
cd /path/to/your/vault
find ./ -type f \( -name "*.jpeg" -o -name "*.png" -o -name "*.jpg" -o -name "*.webp" \) | wc -l

# 找出超過 5MB 的附件
find ./ -type f -size +5M -not -path "*/.obsidian/*"

Windows 用戶可安裝 Vault Statistics 插件， 它會在狀態列即時顯示：筆記數、附件數、連結數、Vault 總大小， 不需要打開終端機。

圖片嵌入語法完全指南

Obsidian 使用 wikilink 語法嵌入圖片，比 Markdown 標準語法更簡潔， 且支援直接控制顯示尺寸——這是多數 Markdown 工具做不到的。 

# 基本嵌入（顯示原始大小）
![[image.png]]

# 指定顯示寬度（px），高度自動等比縮放
![[image.png|400]]

# 含替代文字（alt text）+ 寬度
![[圖表說明.png|系統架構圖|600]]

# 引用外部 Markdown 標準語法（不推薦在 Obsidian 內使用）
![alt text](image.png)

# 嵌入 PDF（顯示第 1 頁）
![[report.pdf]]

# 嵌入 PDF 指定頁面（需 PDF++ 插件）
![[report.pdf#page=3]]

# 嵌入 Excalidraw 繪圖
![[architecture.excalidraw]]

大小控制技巧：使用 ![[image.png|400]] 限制寬度後， 圖片會自動等比縮放。在寬螢幕筆記中建議設定 600–800px；行動裝置閱讀建議 400px 以下。 不設定寬度時，圖片以原始解析度顯示，可能超出筆記可視範圍。

圖片命名規範與 Dataview 搜圖

好的命名規範不只是整齊好看，它直接影響你事後能否快速找到圖片， 也影響 Dataview 查詢的可靠性。Image Converter 插件可以幫你自動命名， 但了解規範背後的邏輯同樣重要。 

# 圖片命名規範建議
# 格式：[筆記主題]-[序號].[副檔名]

# 好的命名範例
專案計劃-1.webp          ✅ 一眼看出歸屬
API設計-架構圖.webp       ✅ 加入描述性詞彙
2025-Q2-roadmap.webp     ✅ 含時間軸資訊

# 差的命名範例
Pasted image 20250301.png  ❌ 預設名，無意義
image.png                  ❌ 極度模糊
1.png                      ❌ 無任何資訊

# Dataview 搜圖查詢（找出特定筆記的所有附件）
```dataview
TABLE file.size as "大小"
FROM ""
WHERE file.extension = "webp" OR file.extension = "png"
WHERE contains(file.folder, "assets/專案計劃")
SORT file.name ASC
```

Dataview 搜圖前提：Dataview 查詢附件需要附件也在 Vault 索引範圍內。 確認設定 → 檔案與連結 → 「偵測所有檔案類型」已開啟， 否則圖片不會出現在 Dataview 查詢結果中。

PDF 嵌入與頁面引用

Obsidian 原生支援 PDF 嵌入，可以直接在筆記內瀏覽 PDF 文件。 搭配 PDF++ 插件，更可以做到精確頁面引用、文字高亮批注、 以及將 PDF 片段轉為可引用的 wikilink——這對學術研究和技術閱讀筆記非常有用。 

# PDF 嵌入語法
![[report.pdf]]               # 嵌入整份 PDF（顯示第 1 頁）

# 使用 PDF++ 插件的進階語法
![[report.pdf#page=5]]        # 從第 5 頁開始顯示
![[report.pdf#page=3&height=400]]  # 指定頁 + 高度限制

# 帶 annotation（批注）的引用
![[report.pdf#page=2&annotation=highlight-1]]

# 文字區塊選取引用（PDF++ 專屬）
# 在 PDF 檢視模式下選取文字後，使用 Ctrl/Cmd+C 複製成 wikilink
![[report.pdf#page=10,0,100,800,200]]

PDF 體積警告：技術手冊類 PDF 動輒數十 MB， 直接存入 Vault 會大幅拖慢同步速度（iCloud / Obsidian Sync 皆受影響）。 建議將大型 PDF 存放在 Vault 外，只在筆記中記錄路徑或外部連結， 或使用 PDF++ 的「外部 PDF 引用」模式。

Excalidraw：手繪風格圖表工作流

Excalidraw 是 Obsidian 社群最受歡迎的視覺化插件之一。 它提供手繪風格的繪圖介面，非常適合製作系統架構圖、流程說明、概念地圖。 繪製完成的 .excalidraw 檔案可以直接嵌入筆記，也可以匯出成 PNG/SVG 供外部使用。 

# Excalidraw 工作流程

# 1. 建立新繪圖
命令面板（Ctrl/Cmd+P）→ Excalidraw: Create New Drawing

# 2. 嵌入到筆記
![[my-diagram.excalidraw]]          # 嵌入完整繪圖
![[my-diagram.excalidraw|800]]      # 指定寬度

# 3. 匯出為靜態圖片（供分享/文件使用）
右鍵圖形 → Export Image → PNG/SVG
# 匯出的 PNG 會自動存入同目錄

# 4. 自動匯出（推薦設定）
Excalidraw 插件設定 → 啟用「Auto-export SVG/PNG」
# 每次儲存 .excalidraw 檔案時，自動同步輸出靜態圖

Excalidraw 嵌入筆記卡片：在 Excalidraw 畫布內， 可以嵌入 Obsidian 的現有筆記——這讓圖表與知識庫之間形成雙向連結。 按住 Ctrl/Cmd 點擊嵌入的筆記卡片，即可直接跳轉開啟。

Excalidraw vs Obsidian Canvas：如何選擇

Obsidian 1.1 後內建了 Canvas（畫布）功能，和 Excalidraw 都是視覺化工具， 但定位不同。Canvas 是「筆記排列板」，Excalidraw 是「繪圖工具」。 理解兩者的差異，可以在正確場景選用正確工具。

功能 Excalidraw Obsidian Canvas
手繪圖形 ✅ 核心功能 ❌ 不支援
嵌入真實筆記卡片 ✅ 支援（需插件） ✅ 原生支援
匯出 PNG/SVG ✅ 支援 ❌ 僅截圖
版本控制（Git） ✅ 純文字 JSON ✅ 純文字 JSON
自訂樣式/字型 ✅ 豐富 ⚠️ 有限
學習成本 中（有操作介面） 低（即插即用）
最適場景 技術圖表、教學示意 筆記地圖、MOC 整理

兩者並用的工作流：用 Canvas 做整體知識地圖（哪些筆記屬於同一主題）， 用 Excalidraw 繪製特定技術概念的說明圖，再用 ![[diagram.excalidraw]] 嵌入到對應的筆記中。 兩者互補，不必二選一。

外部圖片連結 vs 本機圖片：優劣比較

有些使用者習慣直接在筆記中貼入網路圖片 URL，省去管理本機附件的麻煩。 這在短期內看似方便，但長期會帶來問題。以下是兩種方式的完整對比：

面向 本機圖片（推薦） 外部 URL 圖片
離線可用 ✅ 永遠可存取 ❌ 斷網即失效
連結持久性 ✅ 本地路徑穩定 ❌ 外部圖片可能被刪除
Vault 體積 ⚠️ 增加 Vault 大小 ✅ 不增加 Vault 體積
隱私保護 ✅ 完全本地 ❌ 請求外部伺服器
版本控制 ✅ Git 可追蹤變更 ❌ URL 內容可能被替換
適用場景 個人知識庫、長期筆記 暫時性筆記、快速記錄

圖床的正確定位：圖床（如 Imgur、阿里雲 OSS）適合「對外發布」場景， 例如部落格文章或對外分享的文件。但你的 Obsidian Vault 是個人知識庫， 應以本機圖片為主。若要同時發布到外部，再額外上傳到圖床並替換連結。

推薦組合與工作流

根據使用需求選擇插件組合：

  • 一般用戶（輕量）： 原生設定 → 子資料夾 assets/ + Clear Unused Images
  • 進階用戶（推薦）： Custom Attachment Location + Image Converter + Clear Unused Images
  • 需要對外發布： 上述組合 + 阿里雲 OSS / Cloudflare R2 圖床（僅限公開發布的圖片）

本地優先原則：即使你有圖床，Obsidian Vault 內建議保留本地副本。 圖床適合「對外發布」，本地附件才是「知識庫的真正資料」。 斷網狀態下，本地圖片永遠可以存取；雲端圖床不行。

小結

附件管理看起來是小事，但它影響的是整個 Vault 的長期可維護性。 設定好「按筆記名分類」的規則後，你可以放心貼圖，不用擔心哪天找不到， 也不用擔心筆記搬移後圖片斷連。

本章涵蓋了完整的附件管理體系：從資料夾結構策略的設計選擇， 到圖片嵌入語法的精確控制；從 Excalidraw 的手繪圖表工作流， 到 Canvas 的筆記視覺整理；從 PDF 嵌入與頁面引用， 到命名規範與 Dataview 搜圖查詢。

Custom Attachment Location + Image Converter 是這套體系的核心： 前者管「在哪裡」，後者管「長什麼樣子」。兩者搭配，就是目前社群公認最穩的附件管理方案。 下一章我們進入網頁剪藏，看看 Obsidian Web Clipper 如何讓外部內容無縫進入你的知識庫。
