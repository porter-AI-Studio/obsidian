第 14 章 · Part 5：AI 整合：打造 AI 驅動的知識庫

Claude Code + Obsidian：AI 第二大腦完整建置

把 Vault 從「本地筆記 App」升級為「能與 AI 雙向溝通的知識作業系統」

Vault 裡有寶藏，但你挖不出來

你已經在 Obsidian 累積了幾百篇筆記——每日記錄、讀書心得、會議摘要、剪藏文章。 但問你「上個月你對 AI 工具的想法有什麼演變？」，你可能還是要手動翻找半小時。

問題不在筆記，在於你一個人的認知頻寬。 這正是 Claude Code 進場的時機：它能一次讀完你的整個 Vault， 找出你自己都沒發現的脈絡連結，以你習慣的格式輸出摘要、週報、主題索引。

Obsidian 的殺手鐧在於本地 Markdown 檔案。 雲端筆記（Notion、Google Docs）需要 API 才能讓 AI 讀取； Obsidian 的筆記就是你電腦上的 .md 檔案， Claude Code 可以直接讀取、直接修改，不需要任何中介層。

架構三層解耦

整個系統的核心邏輯：把「存哪裡」和「怎麼用」分開。

  • 儲存層（Obsidian）：資料夾結構、雙向連結、視覺化介面——這是你每天打開的 App
  • 資料層（Markdown 檔案）：儲存在本地檔案系統的 .md 純文字——資料的真正形式
  • 智能層（Claude Code）：透過讀寫 Markdown 檔案來分析、整理、連結知識——AI 的操作介面

三層解耦的好處是任一層都可以替換。 未來有更好的 AI 工具，只換智能層；想換筆記 App，只要還是 Markdown 格式，資料一行都不會丟。

Obsidian vs Notion 切換時機：Notion 在 500 頁以下、有團隊協作需求時仍有優勢。Obsidian 適合個人知識資產（1 萬頁仍秒搜）+ AI Agent 整合。從 Notion 遷移時建議只搬最近 6 個月高頻使用的筆記，不要全部遷移。

Step 1：建立基礎資料夾結構

結構清晰的 Vault 讓 AI 更快找到相關內容，也更容易寫出精準的 prompt。 推薦使用 PARA 方法（Projects / Areas / Resources / Archive）：

  • 0-inbox/ — 未分類的新筆記，每天清空到對應位置
  • 1-projects/ — 進行中的專案，每個專案一個子資料夾
  • 2-areas/ — 長期負責的領域（健康、財務、學習、工作）
  • 3-resources/ — 參考資料與研究筆記
  • 4-archive/ — 已完結的項目
  • daily/ — 每日筆記，命名格式 YYYY-MM-DD.md

Step 2：建立 CLAUDE.md — 給 AI 的工作說明書

Claude Code 啟動時會自動讀取工作目錄中的 CLAUDE.md 作為行為指南。 在終端機執行 cd /path/to/your/vault，然後執行 claude。 在 vault 根目錄建立以下 CLAUDE.md： 

# CLAUDE.md — Obsidian Vault 工作說明書

## Vault 結構
- 0-inbox/     → 未分類的新筆記，每天清空
- 1-projects/  → 進行中的專案（一個資料夾一個專案）
- 2-areas/     → 長期負責的領域（健康、財務、學習）
- 3-resources/ → 參考資料與研究筆記
- 4-archive/   → 已完結的項目
- daily/       → 每日筆記

## 你的任務
- 所有筆記使用繁體中文
- frontmatter 必須包含 title, created, tags
- 幫我建立雙向連結（用 [[]] 語法）
- 摘要長度控制在 3 句話以內
- 找到關聯時，在筆記底部加上「## 相關筆記」區塊

## 禁止事項
- 不要刪除任何現有筆記
- 不要修改 daily/ 資料夾的日期格式
- 找不到相關內容時，直接說「找不到」，不要編造

CLAUDE.md 的關鍵在於「禁止事項」——明確告訴 AI 不能做什麼， 比只說能做什麼更能防止意外修改。特別重要的是「不要刪除任何現有筆記」這一條。

Step 3：5 個立刻能用的高頻 Prompt

以下是最常見的 Vault 操作場景。建議存成 Obsidian 的 Template，方便隨時叫出：

週報自動產出

# 高頻 Prompt 1：週報自動產出
請掃描 daily/ 資料夾中本週（週一到今天）的所有筆記，
整理出：
1. 本週完成的事項（從「完成」「done」「✅」等關鍵字識別）
2. 本週學到的新知識（從「學到」「新發現」「TIL」等識別）
3. 本週出現超過 3 次的話題（可能是需要深挖的主題）
4. 下週需要跟進的事項

輸出格式：Markdown，可直接貼到週報模板

跨筆記主題識別

# 高頻 Prompt 2：跨筆記主題識別
請掃描整個 vault，找出在 5 篇以上不同筆記中都出現的主題或概念。
對每個主題：
- 列出提到它的筆記路徑
- 說明這個主題在不同脈絡下的不同意義
- 建議是否值得新建一篇「主題索引頁」

輸出：結構化 Markdown，包含 [[雙向連結]]

其他常用高頻 prompt：

  • 想法歸類：「請讀取 0-inbox/ 的所有筆記，依主題分類並建議移到哪個資料夾」
  • 會議準備：「我明天要和 X 開會，請從 vault 找出過去所有和 X 相關的筆記，整理成一頁簡報」
  • 找連結機會：「請比較這兩篇筆記，找出概念上的相似點和矛盾點，並建議如何建立雙向連結」

LLM Wiki：讓知識庫自動長大

Andrej Karpathy 提出了一個不需要 RAG、不需要 vector database 的知識庫架構：LLM Wiki。 核心思想是把 Vault 分成四層，讓 AI 在每次「Ingest」（攝入新素材）時，知識庫像網一樣自動延伸連結。 

vault/
├── raw/           # 原始素材（逐字稿、PDF 摘錄、會議記錄）
│   ├── 2026-06-01-meeting-abc.md
│   └── 2026-06-03-youtube-video.md
├── wiki/          # AI 整理後的知識條目（一個主題一個檔案）
│   ├── prompt-engineering.md
│   └── vector-database.md
├── index/         # 自動生成的索引頁（按標籤 / 主題）
│   ├── by-tag.md
│   └── by-date.md
└── log/           # Ingest 記錄（哪些 raw 已被處理）
    └── ingest-log.md

運作流程如下：

  1. 把新的原始素材丟進 raw/（一篇文章逐字稿、一份 PDF 摘錄）
  2. Claude Code 執行 Ingest：讀取 raw 素材，判斷與 wiki/ 哪些現有條目相關
  3. 更新相關的 wiki 條目，建立雙向連結，把新知識織進既有知識網
  4. 把處理記錄寫入 log/，更新 index/ 的索引頁

每次 Ingest 之後，知識庫不只多了一筆新資料， 還多了「新資料與既有知識的所有關聯」——這才是「每次都長大一張網」的意義。

一個主題，一個獨立 Vault：Karpathy 建議不同主題的 LLM Wiki 放在不同 vault，不要全部混在一起。主題越集中，Claude Code 讀取時的訊噪比越高，回應品質越好。工作 / 個人學習 / 研究專題各自一個 vault 是常見做法。

Token 節省策略：讓 AI 精準讀取

把整個 Vault 丟給 Claude Code 不是好策略——10,000 頁筆記會消耗大量 token， 而且 AI 搜索效率反而下降。有效控制 token 用量的方法：

  • 在 CLAUDE.md 限定讀取範圍：例如「只需讀取 1-projects/ 和 daily/，其他資料夾不用主動掃描」
  • 用日期限制搜尋範圍：「只看最近 30 天的筆記」比「看全部」省 80% 以上的 token
  • 先問再讀：讓 Claude Code 先列出相關筆記路徑，你確認後再全文讀取
  • 專題 vault 不混用：避免不相關內容干擾 AI 判斷，也讓 CLAUDE.md 更精準

Token 成本提醒：讓 Claude Code 掃描整個 vault 屬於高 token 操作。使用高頻 prompt 時加上範圍限定詞（如「只看 daily/ 本週的筆記」），可將 token 用量降低 90% 以上，而不犧牲答案品質。

每天 30 分鐘的知識儀式

系統建好後，最重要的是建立固定的使用習慣。建議的每日流程：

  1. 打開 daily note（5 分鐘）：記錄今天的三件事、會議、學到的事
  2. 處理 inbox（10 分鐘）：把昨天丟進去的零散內容分類到對應資料夾
  3. 呼叫 Claude Code（15 分鐘）：執行一個高頻 prompt——週一跑主題識別、週五跑週報、其他天跑 inbox 分類或連結建議

30 分鐘的儀式看似短，但 Claude Code 能在這 15 分鐘裡掃描你一週的筆記並輸出結構化分析， 等效於讓助理幫你做了 2 小時的整理工作。

3 個進階工作流

主題演化追蹤

每季讓 Claude Code 掃描 daily/ 過去 90 天的筆記， 找出反覆出現（超過 10 次）的主題，並顯示這個主題在不同時期的觀點演變。 讓你看見自己思考的「成長軌跡」。

個人 RAG 系統

把 vault 作為個人 RAG（Retrieval-Augmented Generation）系統： 在執行任何新任務前，先讓 Claude Code 讀取相關的 wiki/ 條目， 然後在這個「知識脈絡」下完成任務。 等效於讓 AI 在回答問題前先「複習」你所有的相關知識。

知識資產複利化

每季跑一次「主題識別 + 內容延伸」：把過去 90 天 daily 裡反覆出現的主題抓出來， 讓 Claude Code 起草一篇 deep dive 文章草稿。 你加入個人見解後發布——把筆記中的原材料轉化成對外輸出的內容，這就是知識資產的複利效應。

wiki-ingest：讓知識庫自動成長的核心流程

LLM Wiki 的理念說起來簡單，但「如何落地執行」才是關鍵。 wiki-ingest 是一個具體的三步驟循環：收入（Ingest）→ 整理（Compile）→ 連結（Link）。 每次執行後，知識庫不只多了一筆新資料，還多了「新資料與既有知識的所有關聯」。

整個流程的防重複機制靠 wiki/log/ingest-log.md——每次 Ingest 結束後， 已處理的檔案路徑會寫入這份日誌，下次執行時 Claude Code 先讀取日誌再掃描 raw/， 確保每份原始素材只被處理一次。 

# wiki-ingest 指令 Prompt
請執行 wiki-ingest 流程，處理 raw/ 資料夾中所有尚未被處理的檔案。

步驟：
1. 讀取 wiki/log/ingest-log.md，取得「已處理」清單
2. 掃描 raw/ 資料夾，找出「未在清單中」的新檔案
3. 對每個新檔案：
   a. 提取核心概念與實體（人名、工具、術語）
   b. 在 wiki/sources/ 建立摘要頁（格式：摘要-{原始檔案名}.md）
   c. 更新 wiki/concepts/ 中相關概念條目（加入 [[雙向連結]]）
   d. 更新 wiki/entities/ 中相關實體條目
   e. 更新 wiki/index.md 全局索引
4. 完成後，將已處理檔案加入 wiki/log/ingest-log.md

輸出：處理摘要（共處理 N 筆，新建 X 頁，更新 Y 條目）

Ingest 頻率建議：不必每天執行。建議「累積 5-10 份 raw 素材後執行一次」——批次處理比單筆更有效率，Claude Code 也能發現跨素材的共同概念，建立更豐富的連結網絡。

Claude + Obsidian 整合架構：兩種連接方式

Claude Code 與 Obsidian 有兩條整合路徑，適合不同使用情境：

  • 直連方式（推薦）：Claude Code 直接讀寫 vault 資料夾的 .md 檔案。 優點是無需任何外掛或 API，速度最快，也是本章的主要操作模式。
  • MCP Server 方式：安裝 mcp-obsidian（需搭配 Obsidian Local REST API 外掛）， 讓 Claude AI Web 界面也能操作 vault，適合不想打開終端機的使用場景。 安裝步驟：pip install uv → uvx mcp-obsidian → 設定 Obsidian Local REST API 外掛。

Smart Connections、Copilot、Dataview：這幾個外掛在「Obsidian App 內部」做 AI 輔助，與 Claude Code「從外部操作 vault」是互補的，可以同時安裝。Smart Connections 適合即時行內補全；Claude Code 適合批次整理和跨檔案深度分析。

Daily Notes 自動化：從日誌到週摘要

每天的 Daily Note 是最有價值卻最容易被遺忘的知識資產。 透過 Claude Code，可以在每週五讓 AI 掃描全週日誌，自動產生結構化的週摘要—— 不只整理「做了什麼」，還能追蹤「思考如何演變」。 

# Daily Notes → 週摘要 Prompt
今天是 {{date:YYYY-MM-DD}}（週五）
請讀取 daily/ 資料夾中本週所有日誌（週一到今天），
自動產生週摘要，格式如下：

---
title: 週摘要 {{date:YYYY-[W]WW}}
created: {{date:YYYY-MM-DD}}
tags: [週摘要, review]
type: weekly
---

## 本週核心成就
<從各日誌中提取「完成」「done」「✅」「交付」等標記事項，整理為 3-5 條>

## 本週學習快照
<提取「TIL」「學到」「新發現」「發現問題」等關鍵字後的內容>

## 反覆出現的主題（熱點）
<找出在 3 篇以上日誌中出現的主題，附出現次數>

## 下週跟進事項
<提取「TODO」「待確認」「下週」「記得」等標記>

## 本週能量指數
<從日誌語氣推斷：高能 / 正常 / 疲憊，附簡短說明>

請將此週摘要存至：daily/weekly/{{date:YYYY-[W]WW}}.md

週摘要的「能量指數」欄位特別值得注意——Claude Code 從你的寫作語氣（句子長短、用詞積極程度） 推斷本週整體狀態。積累幾個月後，你會看到工作壓力與個人狀態的長期模式， 這是傳統週報做不到的隱含訊息。

Frontmatter 自動補全：讓 AI 整頓舊筆記

大多數人的 vault 都有一批「沒有 Frontmatter」的舊筆記——當初快速記錄， 沒時間加標籤，導致這些筆記很難被 AI 找到、也很難在 Graph View 中分類。 Claude Code 可以批次補全這些缺失的屬性： 

# Frontmatter 自動補全 Prompt
請掃描 vault 中所有缺少標準 Frontmatter 的筆記，
並依照以下規範自動補全：

標準 Frontmatter 格式：
---
title: <從 H1 標題提取，若無 H1 則從檔名推斷>
created: <YYYY-MM-DD，從檔案建立時間或內容推斷>
tags: [<從內容自動推斷 2-5 個標籤>]
type: note | daily | source | concept | project
status: draft | active | archived
---

規則：
- 不修改已有完整 Frontmatter 的筆記
- 若推斷不確定的欄位，在值後加 # TODO
- 輸出：已更新的筆記清單

補全前備份：執行批次 Frontmatter 補全前，建議先用 Obsidian Git 外掛 commit 一次，或直接用 git commit -m "backup before frontmatter patch"。Claude Code 修改大量檔案後若有問題，可以用 git 一鍵還原。

Ollama 整合：隱私筆記的本地 LLM 方案

日記、健康記錄、財務筆記——這些內容你可能不希望上傳到雲端 AI。 Ollama 讓你在本機跑 LLM，Claude Code 可以根據筆記的標籤或位置， 自動切換到本地模型處理敏感內容。 

# Ollama 本地 LLM 整合設定（CLAUDE.md）

## 本地 LLM 切換規則
- 隱私敏感筆記（標有 #private 或在 2-areas/health/）
  → 使用 Ollama（本地，不上雲）
- 一般筆記整理、摘要生成
  → 優先使用 Claude（品質較高）
- 批次 Frontmatter 補全（大量、低思考需求）
  → 使用 Ollama（節省 API 費用）

## Ollama 呼叫方式
```bash
# 在 vault 根目錄建立 .env
OLLAMA_HOST=http://localhost:11434
OLLAMA_MODEL=llama3.2:3b   # 輕量版，適合筆記整理

# 呼叫範例
curl http://localhost:11434/api/generate \
  -d '{"model":"llama3.2:3b","prompt":"整理這篇筆記的重點：...","stream":false}'
```

實際工作流中，建議在 CLAUDE.md 加入切換規則： 標有 #private 的筆記或位於 2-areas/health/ 的內容， 一律走 Ollama；其他批次作業（大量 Frontmatter 補全）也可以切到 Ollama 降低 API 費用。 知識提煉、週摘要等高品質輸出則仍使用 Claude。

推薦 Ollama 模型：llama3.2:3b（輕量，適合 8GB RAM 機器，筆記整理夠用）；gemma3:12b（品質接近 Claude Haiku，需要 16GB RAM）；qwen2.5:7b（中文效果特別好）。透過 ollama list 確認已安裝的模型。

本章小結

Claude Code + Obsidian 的組合威力來自「本地 Markdown = AI 可直接操作的資料格式」這個根本優勢。 透過 CLAUDE.md 設定 AI 行為邊界、建立高頻 prompt 應對日常場景、用 LLM Wiki 讓知識庫自動增長， 你的 Vault 就從「放筆記的地方」變成了真正的 AI 第二大腦。

下一章我們進入更有技術深度的主題——Obsidian CLI 與自訂 AI Skills， 讓 Claude Code 不只能讀寫筆記，還能在 vault 裡執行結構化的自動化流程， 打造屬於你的個人 AI 技能庫。
