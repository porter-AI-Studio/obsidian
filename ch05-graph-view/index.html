第 5 章 · Part 2：核心功能：筆記、連結與關聯圖

關聯圖（Graph View）：視覺化你的知識網絡

把你的第二大腦畫出來，然後從中讀出你還沒意識到的思考模式

從連結到地圖

上一章我們學會了用 [[wikilink]] 在筆記之間建立連結。每一條連結都是一條神經纖維；當你的 Vault 累積了幾十、幾百則筆記，這些纖維交織成一張看不見的網絡。

Graph View 的作用，是把這張網絡畫出來。它是 Obsidian 最受歡迎的招牌功能——許多人第一次打開它，都忍不住說：「哇，這也太像大腦了吧？」那種感覺是有原因的：你看到的不是一個資料庫，而是你思考的地貌。

Graph View 的基本構成

Graph View 的視覺規則很簡單：

  • 一個節點 = 一則筆記：每則筆記都是圖上的一個圓點
  • 一條線 = 一個連結：[[wikilink]] 讓兩個節點之間出現一條邊
  • 節點大小 = 被引用次數：越多筆記連向它，節點就越大
  • 顏色與距離 = 你設定的規則（標籤、資料夾、群組）

從這個圖，你可以一眼看出：哪些主題是你的知識核心（大節點）、哪些筆記形成緊密的叢集（互相引用的群落）、哪些筆記孤立無援（沒有連結的游離點）。

開啟 Graph View：點擊左側工具欄的關聯圖圖示，或使用快捷鍵 Ctrl+G（macOS 為 Cmd+G）。圖上可以用滾輪縮放、拖拉移動，點擊節點即跳轉到該筆記。

全局圖 vs. Local Graph View

Obsidian 提供兩種關聯圖，用途截然不同：

  • 全局圖（Graph View）：顯示 Vault 裡所有筆記的連結網絡。適合用來鳥瞰整體知識結構、找出孤立筆記、觀察知識版圖的平衡度。Vault 越大，全局圖越壯觀，但也越難閱讀——這時候篩選和群組功能就派上用場。
  • Local Graph View（區域圖）：以目前開啟的筆記為中心，向外顯示直接相連、甚至間接相連的鄰近筆記。適合用來寫筆記時找相關素材、確認某一主題的連結是否完整。開啟方式：筆記右上角「更多選項」→「開啟目前筆記關聯圖」。

兩者互補：全局圖看整體結構，Local Graph 看單一主題的脈絡。日常使用中，Local Graph 的實用頻率往往更高。 

# Local Graph View 的 Depth 設定

Depth 預設為 1（只顯示直接相連的筆記）
調高到 2 或 3 可以看到二度、三度關係

→ 適合用來探索「意想不到的連結」
→ Depth 太高（4、5）節點太多，反而難以閱讀
→ 建議日常使用 Depth 2~3

四大功能：讓圖譜真正對你有用

剛打開全局圖，你可能會看到密密麻麻的點和線，完全無法讀取。Graph View 的真正威力需要四個功能才能解鎖。

1. 搜尋：聚光燈模式

在 Graph View 的搜尋欄輸入關鍵字，圖譜會即時濾掉所有不相干的節點，只保留你搜尋的主題及其鄰近脈絡。這個效果像是替整張圖打上聚光燈——你搜尋「行為經濟學」，瞬間看到所有相關筆記在網絡中的位置、它們互相連結的方式，以及通往哪些意想不到的方向。

搜尋的真正價值不是「找到某一則筆記」，而是讓你看見某個主題在整張知識網中的位置與重量。

2. 標籤視圖：主題的衛星

在 Graph View 設定面板中開啟「Tags」選項，標籤會以節點形式出現在圖上，與使用該標籤的筆記相連。你可以立刻看到：哪個標籤底下筆記最多、哪些標籤彼此靠近（主題有關聯）、哪些標籤完全孤立（主題未延伸）。

3. 孤立筆記（Orphan notes）：知識的遺忘角落

開啟孤立連結選項後，圖上會出現那些沒有任何連結的筆記——它們孤零零地漂浮在網絡邊緣。這些孤立節點通常是：

  • 寫完但忘記連結的筆記
  • 從外部剪貼但還沒整合進知識系統的資料
  • 需要進一步延伸或拆分的想法

每隔一段時間掃視孤立筆記清單，是維護知識網絡健康度的好習慣。找到孤立筆記，問自己：「這則筆記跟我的哪些知識有關？」然後補上連結。

4. 群組著色：讓結構浮現

Graph View 允許你依照規則為節點上色。常見規則有三種：

  • 依標籤：tag:#project 全部標成藍色
  • 依資料夾：path:Clippings/ 標成橘色
  • 依字串：標題包含「2026」的筆記標成綠色

當你第一次看到五彩分區的知識地圖，你會突然理解 Obsidian 的魅力：某個領域的筆記遠比你想像的多，某個主題的叢集其實和另一個叢集偷偷相連。群組著色不是視覺效果，而是讓結構可見的工具。 

# 群組著色範例設定（Graph View 設定面板 > Groups）

Group 1：tag:#project    → 藍色（進行中的專案）
Group 2：path:Clippings  → 橘色（外部剪藏資料）
Group 3：tag:#idea       → 黃色（自己的想法與洞見）
Group 4：tag:#permanent  → 綠色（永久筆記 / Zettelkasten）

→ 目的不是上色，而是讓不同性質的筆記在圖上一目了然
→ 可以立刻看出「自己的想法」和「外部資料」的比例是否平衡

Local Graph 進階操作技巧

Local Graph View 遠比許多人想像的更強大。掌握幾個進階技巧，你可以用它做精準的主題偵察，而不只是「看看附近有什麼筆記」。

圖譜健康度：怎麼判斷你的知識網絡狀況

打開 Graph View，你眼前的那張圖不只是「好看」或「不好看」——它是你知識系統的健康報告。學會看懂以下幾種模式，你就能快速判斷 Vault 目前的狀態需要什麼調整。

四種常見的圖譜問題與處方

  • 一片散點（孤立節點 > 50%）：表示你在寫筆記，但沒在建立連結。處方：每次寫完筆記，強制問自己「這則筆記和哪三則現有筆記有關？」，立刻補上 [[wikilink]]。
  • 超大單極（一個節點吸引幾乎所有連結）：表示你有一個「萬能索引」筆記，什麼都連到它。處方：把這個節點拆解成幾個更具體的主題頁，讓連結分散到對應的主題。
  • 幾個叢集但完全不相連：表示你在不同領域的思考還沒交叉。處方：專門建立「橋接筆記」（bridge note），一則筆記同時連向兩個不同叢集，讓知識開始對話。
  • 所有節點大小相近：表示你沒有知識重心，或者連結分布過於均勻。處方：認真建立幾則「永久筆記」（evergreen note），讓它們成為你真正關注的核心主題，讓其他筆記連向它們。

橋接節點（Bridge Note）是圖譜健康度的關鍵指標。一則橋接筆記同時連向兩個不同叢集，讓原本分離的知識領域開始互動——這往往是洞見誕生的地方。Graph View 中，橋接節點看起來像是兩個叢集之間的「樞紐」，刻意培養它們，你的知識網絡會從「各自獨立的孤島」進化成「相互交流的大陸」。

用 Graph View 找寫作靈感

Graph View 最實用的應用之一，是在你準備寫作或研究時，用來激發靈感、找出意外的連結。這個方法特別適合用 Local Graph View 實作：

三步驟流程

  1. 加標籤，區分資料來源：在筆記上加上標籤，區分「別人的資料」（#書、#影片、#文章）和「自己的想法」（#想法、#洞見）。
  2. 用篩選語法聚焦主題：在 Local Graph View 的搜尋欄輸入 line:(關鍵字)，圖上只顯示內文包含這個關鍵字的筆記。深度調到 2~3，你會看到主題周邊的完整脈絡。
  3. 觀察連結，問自己「如果連起來呢？」：看到兩則「自己的想法」筆記出現在同一個主題圖上，問：如果把它們連結在一起，能產生什麼新觀點？這個過程常常讓你寫出完全沒預料到的內容。

Local Graph 篩選語法：line:(關鍵字) 會搜尋筆記內文含有該關鍵字的所有筆記；tag:#書 則篩選特定標籤。兩者可以組合使用，快速鎖定目標主題範圍。

這個流程的本質，是把 Obsidian 的知識網絡當作一個「思緒片段庫」——你過去積累的每一則想法都是可用的素材，Graph View 讓你一眼看到哪些片段可以組合在一起，產生超出個別筆記的新洞見。

養成「寫→連→看」的循環

Graph View 的價值不是一次性的。它是一個你需要定期回訪的工具，用來觀察知識網絡的狀態：

  • 寫完筆記：加上連結，確保它不是孤立節點
  • 每週或每月：打開 Graph View，看看最近新增的節點有沒有形成有意義的叢集
  • 發現異常：孤立節點太多？某個標籤的筆記突然暴增？這些都是值得注意的訊號

注意：Graph View 的前提是你有在建立連結。如果你的 Vault 裡所有筆記都是孤立的，Graph View 只會顯示一堆散點，沒有任何洞察可言。先養成 [[wikilink]] 的連結習慣（見上一章），Graph View 才能真正發揮作用。

知識網絡的成長不是線性的，而是有臨界點的：當連結密度達到某個程度，你在 Graph View 裡看到的不再是散點，而是真正的結構——主幹、支線、叢集、橋接節點。那個瞬間，你會第一次清楚看見自己的思考地貌是什麼形狀。

小結

Graph View 是 Obsidian 最具辨識度的功能，但它的價值不在於好看，而在於讓思考的結構可見。全局圖給你鳥瞰視野，Local Graph 給你主題聚焦，搜尋、標籤、孤立節點、群組著色四個功能讓你真正讀懂圖上的資訊。
