多終端同步：手機、電腦、平板一致體驗

五種方案選型指南，從零到跨裝置無縫切換

Obsidian 最大的優勢是「本地優先」——筆記存在你自己的硬碟，沒有廠商鎖定，永遠可以存取。 但這也帶來了一個現實問題：不同裝置之間的資料，預設是彼此隔離的。

你在電腦上寫的晨間日記，手機裡看不到；在咖啡廳用 iPad 剪藏的文章，回到辦公室也不見蹤影。 若不設定同步，Obsidian 的知識庫就只是單一裝置的孤島。

好消息是：Obsidian 的筆記全部是標準的 Markdown 純文字檔，任何可以同步檔案的工具都能使用。 社群因此發展出五條不同路線，各有其適用場景與代價。本章帶你一次看清楚，找到最適合你的方案。

方案一：Obsidian Sync（官方，最省心）

Obsidian 官方推出的付費同步服務。 開啟後一切自動化：筆記、插件設定、主題、甚至 hotkey 都會一起同步。

端到端加密是其核心承諾——Obsidian 的伺服器看不到你的資料內容。 如果你願意每月花一杯咖啡錢換取零配置的跨裝置體驗，這是最直接的選擇。

價格查證（2026-09 查證）：本章原先標示的 $10 美元/月（或 $96/年）已經過時。依 Obsidian 官網 obsidian.md/pricing 當下公告，Sync 現行價格是年繳 $4 美元/月，或月繳 $5 美元/月，較本章原先數字低不少；官網未再列出裝置數量上限等細節，實際額度請以官網當下頁面為準，訂閱前務必重新核對一次。

官方 Sync 特別適合： 非技術用戶、重度 iOS 使用者、不想折騰的知識工作者。

方案二：第三方雲端硬碟（免費入門）

macOS + iPhone 用戶可以把 Vault 放在 iCloud Drive；Windows 用戶可以選 OneDrive。 電腦端幾乎零配置，只要把 Vault 資料夾建在雲端同步目錄內即可。

主要風險在 iOS 端： iCloud 的 iOS 同步機制可能產生衝突檔案（conflict file）， 在雙向快速編輯時偶發性地製造出 filename.md.conflict.md 這類重複檔案。 如果你只用電腦主力寫作、手機偶爾查看，此方案完全夠用。

方案三：Remotely Save + WebDAV（推薦免費方案）

Remotely Save 是 Obsidian 社群最受歡迎的免費同步插件，支援多種後端：

  • WebDAV（堅果雲、自建 Cloudreve、NAS）
  • Amazon S3 / Cloudflare R2
  • Dropbox / OneDrive

對台灣用戶來說，堅果雲免費版（1GB 流量/月）搭配 Remotely Save 是最簡單的方案—— 堅果雲提供 WebDAV 存取，不需要任何伺服器。 

# 在 Obsidian 安裝 Remotely Save 插件
# 路徑：設定 → 社區插件 → 瀏覽 → 搜尋 Remotely Save → 安裝並啟用

# 插件設定（以堅果雲 WebDAV 為例）
Remote Service: WebDAV
Server Address: https://dav.jianguoyun.com/dav/
Username:       你的堅果雲帳號（Email）
Password:       你的 WebDAV 應用密碼（非登入密碼）
Remote Base Dir: obsidian-vault  # 在雲端建立的資料夾名稱

# 完成後點「測試連線」，成功後按「立即同步」

注意：堅果雲 WebDAV 密碼需要在堅果雲官網「帳號設定 → 安全設定 → 第三方應用管理」另行產生， 不是你的登入密碼。

方案四：Syncthing（離線優先，隱私最高）

Syncthing 是一套開源的 P2P 同步工具，裝置之間直接傳輸，不經過任何雲端伺服器。 速度比雲端方案快 3~5 倍（區域網路下接近滿速），且所有資料從不離開你掌控的設備。

限制：兩台裝置必須同時開機才能同步；iOS 端需要購買 MobiusSync（約 $7 美元，一次性）。 如果你的主要場景是「公司電腦 ↔ 家用電腦」或「電腦 ↔ Android 手機」，Syncthing 是體驗最流暢的免費方案。

方案五：Obsidian Git（開發者的版本控制）

如果你已經熟悉 Git，把 Vault 放在 GitHub Private Repo 是最強的方案—— 每一次修改都有完整歷史紀錄，誤刪筆記可以隨時復原，免費且容量幾乎無限。

安裝 Obsidian Git 插件後，它會定時自動 commit + push，你完全不需要手動操作。 

# 前置條件：安裝 Git 並設定 GitHub 帳號
git config --global user.name "你的名字"
git config --global user.email "你的Email"

# 在 Vault 根目錄初始化 Git
cd /path/to/your/vault
git init
git remote add origin https://github.com/你的帳號/obsidian-vault.git

# 第一次推送
git add .
git commit -m "init: Obsidian vault"
git push -u origin main

# Obsidian Git 插件設定（設定 → 社區插件 → Obsidian Git）
Auto pull interval:  10  # 每 10 分鐘自動拉取
Auto push interval:  10  # 每 10 分鐘自動推送
Commit message:      vault backup: {{date}}

缺點：iOS 端幾乎不可行（App Store 政策限制 Git 操作）， Android 端需要額外 App（如 MGit）且設定繁瑣。 建議只作為電腦端的備份與版本控制，搭配其他方案在行動端補強。

Git 同步必備：.gitignore 設定

將 Vault 放進 Git 時，有些檔案不應該被追蹤：裝置特定的工作區快取、OS 系統檔、 以及可能含有敏感資訊的資料夾。在 Vault 根目錄建立 .gitignore 可以精準控制同步範圍。 

# Obsidian Vault .gitignore 範本
# 工作區設定（包含裝置特定設定，通常不想同步）
.obsidian/workspace.json
.obsidian/workspace-mobile.json

# 快取與暫存
.obsidian/cache
.trash/

# OS 系統檔
.DS_Store
Thumbs.db
desktop.ini

# 如果有敏感筆記資料夾，可加入排除
# private/
# diary/

# 大型附件（超過 GitHub 50MB 限制）
# *.pdf
# *.mp4
# *.zip

# 插件編譯產物
.obsidian/plugins/*/node_modules/
.obsidian/plugins/*/*.js.map

技巧：.obsidian/workspace.json 記錄的是「目前開啟哪些分頁」， 每次切換都會變動。將它加入 .gitignore 可以避免每次開關 Obsidian 就產生 commit。

選型建議：怎麼選最適合你的方案？

根據你的使用情境快速選擇：

  • 不想折騰，願意付費： → Obsidian Sync
  • Mac + iPhone 用戶，筆記量不大： → iCloud Drive
  • 想免費、全平台（含 iOS）： → Remotely Save + 堅果雲 WebDAV
  • Android + 電腦，重視隱私： → Syncthing
  • 開發者，需要完整版本歷史： → Obsidian Git（電腦端）+ 其他方案（手機）

進階用法： 多種方案可以混搭。例如使用 Obsidian Git 作為版本控制與備份， 同時開啟 Remotely Save 讓 iOS 裝置也能存取——兩者互不干擾，各司其職。

同步衝突怎麼處理？

無論使用哪種方案，「同步衝突」都是無法完全避免的情況——當你在兩台裝置同時修改同一份筆記時， 系統需要決定以哪個版本為準。

幾個避免衝突的實用原則：

  • 切換裝置前，先同步再開啟，確保拿到最新版本
  • 同一份筆記盡量只在一台裝置上主力編輯
  • 使用 Obsidian Git 時，設定 auto pull 頻率高於 auto push
  • 發現衝突檔案（.conflict.md）時，比對兩份內容後手動合併
# Git 衝突解決工作流程

# 1. 查看有哪些衝突檔案
git status

# 2. 開啟衝突檔案，手動合併
# 衝突標記格式：
# <<<<<<< HEAD
# 你的本地版本內容
# =======
# 遠端版本內容
# >>>>>>> origin/main

# 3. 編輯後移除衝突標記，保留正確內容

# 4. 標記為已解決並提交
git add 衝突的筆記.md
git commit -m "fix: resolve sync conflict in 衝突的筆記.md"

# 5. 推送
git push

# ── 預防衝突的 Git 設定 ──
# 使用 rebase 取代 merge，減少衝突提交
git config pull.rebase true

# 設定較短的 auto-pull 間隔（Obsidian Git 插件）
# Pull interval: 5 分鐘（比 push 頻率更高）

備份策略：3-2-1 原則

同步不等於備份。同步只保證多台裝置內容一致，但如果你不小心刪除了一個重要資料夾， 所有裝置都會同步這個「刪除」操作。真正的備份需要獨立、可回溯的副本。

資訊安全領域的 3-2-1 備份原則：

對 Obsidian 用戶的實際建議：

  • 第 1 份：本機 Vault（主要工作位置）
  • 第 2 份：雲端同步（Remotely Save / Obsidian Sync）
  • 第 3 份：GitHub Private Repo 或每週本地壓縮備份
#!/bin/bash
# Obsidian Vault 自動備份腳本
# 建議放在 ~/scripts/backup-vault.sh，加入 crontab 每日執行

VAULT_PATH="$HOME/Documents/ObsidianVault"
BACKUP_DIR="$HOME/Backups/obsidian"
DATE=$(date +%Y-%m-%d)
KEEP_DAYS=30  # 保留最近 30 天備份

# 建立備份目錄
mkdir -p "$BACKUP_DIR"

# 壓縮備份
tar -czf "$BACKUP_DIR/vault-$DATE.tar.gz"   --exclude="$VAULT_PATH/.obsidian/cache"   --exclude="$VAULT_PATH/.trash"   "$VAULT_PATH"

echo "備份完成：$BACKUP_DIR/vault-$DATE.tar.gz"

# 清理超過 30 天的舊備份
find "$BACKUP_DIR" -name "vault-*.tar.gz" -mtime +$KEEP_DAYS -delete
echo "已清理超過 $KEEP_DAYS 天的舊備份"

# crontab 設定（每天凌晨 3 點執行）：
# 0 3 * * * /bin/bash ~/scripts/backup-vault.sh >> ~/logs/vault-backup.log 2>&1

重要：定期測試備份的可還原性。每個月花 5 分鐘，從備份中還原一個測試資料夾， 確認備份真的可以用，而不只是「存在那裡」。

行動裝置同步實戰建議

行動端（iOS / Android）的同步體驗與電腦端有些差異，以下是幾個常見問題與對應方法：

  • iOS + iCloud：在 iOS 版 Obsidian 開啟 Vault 時，選擇「Store in iCloud」。 注意：切換到其他 App 後，iCloud 可能需要數秒才會同步完成，回來時要等一下再編輯。
  • iOS + Remotely Save：每次打開 Obsidian，插件會自動觸發同步。 若想確保同步完成，可以在插件設定中開啟「Sync on start」與「Sync on close」。
  • Android + Syncthing：安裝 Syncthing-Fork（免費），設定 Vault 資料夾為同步目標。 在背景持續運行時需要允許電池優化豁免。
  • Android + Obsidian Git：安裝 Termux + Git，或使用 MGit App 手動 pull/push。 適合有技術背景的用戶。

行動端建議：如果主要在電腦工作、手機只是查閱，可以選「唯讀同步」策略—— 手機只 pull 不 push，避免在小螢幕上誤觸修改導致衝突。

Syncthing 詳解：P2P 架構與設定

Syncthing 的核心優勢是去中心化——裝置之間直接同步，沒有任何中間伺服器。 這意味著你的筆記從未離開你的裝置網路，隱私保護達到最高等級。

Obsidian Sync 進階：版本歷史與加密設定

付費使用者常常沒有充分利用 Obsidian Sync 的進階功能。 版本歷史（Version History）讓你可以回溯到任意時間點的筆記狀態， 而端到端加密密碼確保即使 Obsidian 伺服器遭入侵，你的資料也無法被解讀。 

# Obsidian Sync 進階設定（CLI 與 API 層級）

# Obsidian Sync 儲存庫列表（官方 API，僅供參考）
# GET https://sync.obsidian.md/vault/list
# Authorization: Bearer <your_api_key>

# 選擇性同步設定（在 Obsidian 設定 → 同步）
# 可個別開關以下項目同步：
# ✅ 插件設定（Settings files）
# ✅ 插件本體（Installed plugins）
# ✅ 佈景主題（Themes）
# ✅ 片段樣式（CSS snippets）
# ❌ 工作區佈局（Workspace layout）← 建議關閉，避免視窗狀態互相覆蓋

# 版本歷史回溯（Version History）
# 官方 Sync 保留最近 1 年的版本歷史
# 操作方式：右鍵點擊筆記 → View version history
# 可逐版本預覽 diff，選擇恢復到任意時間點

# 端到端加密密碼（Encryption password）
# 設定後，雲端伺服器無法解讀你的筆記內容
# 重要：密碼遺失無法恢復，請存入密碼管理器！
# 建議：使用 Bitwarden / 1Password 保存

加密密碼警告：啟用端到端加密後，密碼遺失即永久無法解密。 請務必在密碼管理器（如 Bitwarden、1Password）中儲存此密碼， 且所有裝置都需要輸入相同密碼才能解密同步內容。

Git Hooks：讓版本控制更聰明

Git 的 Hooks 機制讓你可以在每次 commit 前後自動執行腳本。 對 Obsidian Vault 來說，最實用的是 pre-commit hook—— 可以自動偵測敏感資訊、更新 frontmatter 的修改日期，甚至觸發 Lint 檢查。 

#!/bin/bash
# Obsidian Vault Git Hooks：自動化品質把關
# 放在 .git/hooks/pre-commit，chmod +x 後生效

echo "🔍 Pre-commit: 檢查筆記品質..."

# 1. 禁止提交包含私密關鍵字的筆記
SECRETS_PATTERN="(password|secret|api.key|token)s*[:=]s*['"]?[a-zA-Z0-9]"
if git diff --cached --name-only | xargs grep -lEi "$SECRETS_PATTERN" 2>/dev/null; then
  echo "❌ 偵測到可能的敏感資訊！請確認後再提交。"
  exit 1
fi

# 2. 自動更新 modified 日期（frontmatter）
for file in $(git diff --cached --name-only | grep ".md$"); do
  if [ -f "$file" ]; then
    TODAY=$(date +%Y-%m-%d)
    # 若 frontmatter 有 modified 欄位則更新
    sed -i.bak "s/^modified: .*/modified: $TODAY/" "$file"
    rm -f "$file.bak"
    git add "$file"
  fi
done

echo "✅ Pre-commit 檢查通過"
exit 0

# ── 安裝方式 ──
# cp pre-commit .git/hooks/pre-commit
# chmod +x .git/hooks/pre-commit

自動更新 modified 日期：搭配 Templater 插件， 可以在筆記 frontmatter 中維護 created 與 modified 兩個欄位。 透過 pre-commit hook 自動更新 modified，讓你的 Git 歷史同時也是完整的筆記時間軸。

小結

同步方案沒有唯一正確答案，只有最適合你當前習慣的選擇。 建議從最簡單的方案開始——免費用戶先試 Remotely Save + 堅果雲， 如果覺得配置麻煩就升級 Obsidian Sync，如果你是開發者就直接上 Git。

無論選哪種同步方案，記得額外設定獨立備份。同步確保「即時一致」，備份確保「可以回頭」，兩者缺一不可。

至此，你已經掌握了 Obsidian 從基礎筆記、插件生態、AI 整合到跨裝置同步的完整工作流。 知識管理系統的終極目標不是「工具最完美」，而是「你會持續使用」。 選一個讓你感覺自然的組合，開始積累，知識自會隨時間複利增長。
