第 12 章 · Part 4：Web Clipper 與資訊收集

Obsidian Web Clipper：一鍵剪藏網頁到 Vault

從「看到好文章→手動複製貼上」到「一鍵剪藏、AI 摘要、自動歸檔」的跨越

資訊收集的斷點問題

每個知識工作者都面臨同一個痛苦：你在瀏覽器裡讀到一篇好文章，想存進 Obsidian， 卻要經歷「複製標題→新建筆記→貼上內容→補充來源連結→手動加 frontmatter」這一串繁瑣動作。 幾次之後，你開始用「書籤」代替，最後這些書籤再也沒被打開過。

Obsidian Web Clipper 是 Obsidian 官方出品的瀏覽器擴充功能， 目標就是消除這個斷點。它讓你在網頁上按一下，選擇模板， 自動產生帶有結構化 frontmatter 的 Markdown 筆記並送進 Vault——不需要開 Obsidian，不需要切換視窗。

安裝與初始設定

Web Clipper 支援 Chrome、Firefox、Safari 等主流瀏覽器。

步驟一：安裝瀏覽器擴充

前往各瀏覽器的擴充商店搜尋「Obsidian Web Clipper」， 或從 Obsidian 官方 GitHub（obsidianmd/obsidian-clipper）下載。安裝後瀏覽器工具列會出現 Obsidian 圖示。

步驟二：設定 Vault 路徑

點擊擴充圖示 → 進入設定 → 在「Vault」欄位輸入你的 Obsidian Vault 名稱（不是完整路徑，只是 Vault 的名稱）。 Web Clipper 透過 Obsidian 的 URI scheme（obsidian://）與本機 App 溝通， 所以 Obsidian 必須在你的電腦上已安裝並開啟過一次。

行動裝置也可用：iOS 上用 Safari 加上書籤小工具（Bookmarklet）即可剪藏；Android 可用 Firefox + 擴充或 Obsidian 的分享功能。官方文件有詳細的逐平台教學。

步驟三：匯入或建立模板

Web Clipper 的核心是模板（Template）。 每個模板定義了剪藏後筆記的 frontmatter 欄位、內容格式與存放位置。 你可以從網路上下載現成的 JSON 格式模板匯入，也可以自行在設定介面建立。

模板語法快速入門

Web Clipper 模板使用兩類語法：

  • 內建變數：由擴充自動提取的頁面資訊
  • AI 提取器：透過 AI 模型從頁面內容生成指定欄位

常用內建變數

{{title}}         // 網頁標題
{{url}}           // 完整 URL
{{date}}          // 今天日期（格式可自訂，如 {{date:YYYY-MM-DD}}）
{{time}}          // 當前時間
{{domain}}        // 網域（如 github.com）
{{author}}        // 頁面作者（若頁面有 meta 標籤）
{{content}}       // 頁面正文（Markdown 格式）
{{highlights}}    // 你在頁面上用滑鼠選取的文字

完整 frontmatter 模板範例

---
title: "{{title}}"
source: "{{url}}"
author: "{{author}}"
created: {{date:YYYY-MM-DD}}
tags:
  - clippings
  - {{domain}}
---

> [!abstract] AI 摘要
> {{ai:請用繁體中文，2–3 句話總結這篇文章的核心觀點}}

## 原文重點

{{content}}

{{ai:...}} 語法：雙大括號裡以 ai: 開頭，後面接 prompt，Web Clipper 會在剪藏時呼叫你設定的 AI 服務（OpenAI、Anthropic 等）即時生成內容。這是本章最強大的功能，下一章會深入介紹 prompt 設計技巧。

格式化語法：將 AI 輸出包進 Callout

Web Clipper 的格式化語法可以讓 AI 輸出自動套用 Obsidian 的 Callout 樣式， 讓筆記視覺上更清晰： 

> [!quote] 黃金圈摘要
> {{ai:用 Why-How-What 結構分析這篇文章，每段一行，共三行}}

實際剪藏流程示範

以剪藏一篇技術文章為例：

  1. 在瀏覽器開啟目標網頁
  2. 點擊工具列的 Web Clipper 圖示
  3. 從下拉選單選擇你的模板（如「通用摘要模板」）
  4. 預覽視窗顯示即將建立的筆記內容，包括 AI 正在生成的摘要
  5. 點擊「Add to Obsidian」——筆記立刻出現在 Vault 的指定資料夾

整個過程不需要切換到 Obsidian App，也不需要手動填寫任何欄位。 如果你有配合 Templater 或 Auto Note Mover（見第 10 章）， 筆記還會自動依標籤移動到正確的分類資料夾。

剪藏不只是網頁：多種來源支援

Web Clipper 能處理的內容遠不只是一般網頁：

  • YouTube 影片：可提取影片標題、頻道、時長，搭配 AI 生成影片摘要（需字幕存在）
  • Twitter / X 推文串：完整保存推文與所有回覆
  • 學術論文（arXiv、PubMed）：提取作者、摘要、發表日期
  • GitHub Repository：保存 README 與 star 數等資訊
  • 中文平台：B 站、微信公眾號等需要使用社群維護的中文增強版（obsidian-clipper-cn）

中文增強版：官方版 Web Clipper 對部分中文平台支援有限。社群開發者 Next蔡蔡 維護的 obsidian-clipper-cn（GitHub: nextcaicai/obsidian-clipper-cn）額外支援 B 站影片字幕提取與飛書文件剪藏，台灣和中國用戶可考慮使用。

進階整合：搭配 Make.com 打造全自動流水線

Web Clipper 是資訊收集的起點，但「收集完放著不用」是許多人的痛點。 結合自動化工具 Make.com，可以把零散的剪藏筆記進一步加工成可發布的內容。

架構概覽

以下是一個完整的 AI 快訊生成工作流架構：

[網頁 / 推文 / YouTube]
    ↓ Web Clipper（一鍵剪藏 + AI 摘要）
[Obsidian Vault]
    ↓ Make.com 聚合工作流（定時觸發）
    ↓ AI 提取各筆記核心觀點
    ↓ 組合成完整 AI 快訊草稿
[草稿筆記（等待人工確認）]
    ↓ 人工加入個人見解 + 確認發布
    ↓ Make.com 發布工作流（Webhook 觸發）
[WordPress / Twitter / 微信公眾號]

系統設計的關鍵原則：解耦

這個架構最重要的設計決策是把「內容生成」和「內容發布」拆成兩個獨立的工作流。 好處是：

  • 生成流不需要知道要發到哪裡——它只負責把加工後的草稿交給發布流
  • 發布流可以隨時新增平台——今天連 WordPress，明天加 Medium，完全不影響生成邏輯
  • 保留人工確認節點——AI 生成的草稿先暫停，等人加入個人觀點再觸發發布

為什麼不全自動發布？ 在 AI 時代，帶有個人見解和思考的文字比純 AI 生成的內容更有價值。建議保留「人工確認」這個環節，而不是讓系統完全自動發布——這樣你的讀者得到的是你的觀點，而不只是 AI 的整合。

Obsidian Base 功能：管理你的剪藏資料庫

Obsidian 新推出的 Base（資料庫）功能，讓你可以把剪藏筆記像試算表一樣管理。 配合 Web Clipper 產生的標準化 frontmatter，你可以：

  • 用表格視圖瀏覽所有剪藏，依日期、來源、標籤排序篩選
  • 快速找到某個網域（如 github.com）的所有剪藏
  • 追蹤哪些文章已讀、哪些還沒整理

這讓 Obsidian 的角色從「筆記 App」進化成真正的「個人知識資料庫」。 更多 Base 功能的使用方式，可以參考 Dataview 那章（第 9 章）的查詢邏輯——兩者的設計哲學相通。

常見問題

剪藏後筆記跑到根目錄怎麼辦？

在模板設定裡指定「Folder」欄位，例如填入 Clippings/， 所有用這個模板剪藏的筆記都會存到 Vault 下的 Clippings 資料夾。 搭配 Auto Note Mover 可以進一步依標籤自動分類到子資料夾。

AI 摘要功能需要付費嗎？

Web Clipper 的 AI 功能需要你自行提供 API Key（支援 OpenAI、Anthropic Claude、Ollama 等）。 使用 OpenAI GPT-4o mini 或 Claude Haiku 成本較低，每篇摘要費用通常不到 0.01 美元。 如果你有架設 Ollama 本地模型（見第 14、15 章），也可以完全免費使用 AI 功能。

剪藏的圖片會消失嗎？

Web Clipper 預設保留原始圖片的網路連結（![](https://...)）， 不會把圖片下載到 Vault。這表示如果來源網站移除圖片，你的筆記裡也會看不到。 若需要永久保存圖片，可以配合 Obsidian 的附件管理插件（見第 11 章）手動下載， 或在模板中使用 {{localImage}} 變數（需要額外設定）。

剪藏類型選擇指南

Web Clipper 不只能「全文剪藏」，根據使用情境選擇合適的剪藏類型， 能讓 Vault 裡的資訊更精準、雜訊更少。

選擇策略：對於 80% 的網頁，「書籤快存」搭配 AI 快速摘要就夠用；只有真正需要反覆參考的技術文章或學術論文，才值得做「全文剪藏」。過度收集全文會讓 Vault 變成難以消化的資訊垃圾場。

Clipper 模板深度設定

模板是 Web Clipper 最核心的設定，好的模板設計能讓每一筆剪藏都帶著標準化的 metadata， 方便後續用 Dataview 或 Obsidian Base 進行查詢與管理。

自動化 Tag 策略

在 frontmatter 的 tags 欄位加入 {{domain}}， Web Clipper 會自動根據網域建立 tag，例如：

  • github.com → tag: github
  • arxiv.org → tag: arxiv
  • youtube.com → tag: youtube

加上固定的 clippings tag，你就能在 Dataview 或 Obsidian Base 中 用 WHERE contains(tags, "clippings") 快速過濾所有剪藏筆記。

status 欄位：追蹤處理進度

建議在 frontmatter 加入 status 欄位，搭配固定的工作流：

  • unread：剛剪藏，尚未閱讀
  • reading：正在閱讀或整理
  • processed：已整理並加入 [[wikilink]] 連結
  • archived：已移入主題資料夾，完成歸檔

搭配 Obsidian Base 管理狀態：在 Base 視圖中，可以建立 status 欄位的下拉選單，直接在表格中點擊更新狀態，無需開啟每一篇筆記。這比手動編輯 frontmatter 效率高數倍。

剪藏後的整理工作流

「收集」是起點，但如果剪藏的筆記一直堆積在 Clippings 資料夾而沒有被處理， Web Clipper 就只是換了個地方存書籤而已。 真正讓剪藏產生價值的，是建立一套可持續的整理工作流。

每日 Inbox 快速回顧（5–10 分鐘）

把「快速過一次 Inbox」加入每日回顧（Daily Notes）的固定儀式：

  1. 用 Obsidian Base 開啟 status = unread 的篩選視圖
  2. 瀏覽筆記標題和 AI 摘要——大部分都可以在 30 秒內判斷是否值得深讀
  3. 不值得深讀的：直接改 status: archived，讓 Auto Note Mover 歸入封存區
  4. 值得深讀的：改 status: reading，排入當週待讀清單

每週深度整理（30–60 分鐘）

每週固定一段時間，處理所有 status = reading 的筆記：

  • 精讀，補充「我的想法」區塊
  • 加入 [[wikilink]] 連結到相關概念筆記
  • 決定歸入哪個主題資料夾，更新 status: processed
  • 若內容夠重要，摘錄至對應的 MOC（Map of Content）筆記

避免「囤積症」：如果 Inbox 裡超過 50 篇未讀，通常是收集標準太低造成的。建議做「剪藏時就決定」的練習——只剪藏你在 30 天內有 70% 以上機率會用到的內容，而不是「先存起來以後再說」。

與第三方工具整合

Web Clipper 是 Obsidian 生態系的核心剪藏工具，但市面上還有幾個工具可以和它形成互補。

Readwise Reader：閱讀層的增強

Readwise 是專注於「閱讀管理」的付費工具， 其 Reader 功能提供優化的文章閱讀體驗、行內高亮、Kindle / 電子書同步， 以及把所有高亮自動匯出到 Obsidian 的整合。

  • Readwise 的優勢：自動複習機制（Spaced Repetition）、多來源高亮整合（Kindle、Twitter、Web）、每日回顧郵件
  • 搭配方式：在 Readwise 裡高亮 → 自動同步到 Obsidian 的 Readwise 資料夾 → Web Clipper 處理快速剪藏 → 兩套資料都進 Vault
  • 費用：官網公告價曾為 $7.99/月或 $79.99/年，但 2026-09 查證時 Readwise 官網顯示現行價格已調漲為年繳 $9.99/月（合計 $119.88/年）或月繳 $12.99/月，請以 Readwise 官網當下顯示的價格為準，書中舊數字僅供參考

Readwise vs Web Clipper 選哪個？ 若你大量閱讀英文文章且重視複習機制，Readwise 值得投資。若你主要是繁中內容、偶爾剪藏，官方 Web Clipper 免費且夠用。兩者也可以並用：Web Clipper 處理快速書籤，Readwise 處理深度閱讀。

Hypothesis：學術標記與協作

Hypothesis 是開源的網頁標記工具， 讓你在任何網頁或 PDF 上加入公開或私人的註記，並支援匯出至 Obsidian。

  • 適合學術研究者：可以看到同一篇論文上其他研究者的公開標記
  • 透過 Obsidian Hypothesis 插件可將所有標記自動同步到 Vault
  • 適合協作場景：團隊成員可以共同在文件上標記討論

Instapaper / Pocket：稍後閱讀佇列

傳統的稍後閱讀服務（Instapaper、Pocket）可以透過 Make.com 或 Zapier 的自動化， 在你標記文章為「已讀」或「加星號」時，自動觸發 Web Clipper 剪藏到 Obsidian， 形成「稍後閱讀 → 深度閱讀 → 剪藏存檔」的三段式工作流。

手機端剪藏完整指南

大量的好文章是在手機上瀏覽時發現的，手機端的剪藏體驗直接影響知識收集的完整性。

iOS / iPadOS：Safari Bookmarklet 方法

官方提供 Safari Bookmarklet（書籤小程式）方案：

  1. 在 Obsidian Web Clipper 設定頁面，找到「iOS Safari Bookmarklet」下載連結
  2. 在 Safari 中開啟連結並加入書籤
  3. 之後在任何網頁，點擊 Safari 的書籤圖示 → 找到 Obsidian Clipper 書籤，執行
  4. 選擇模板後，App 會自動切換到 Obsidian 完成儲存

Android：Firefox 擴充方法

Android 上的 Firefox 支援安裝桌面版擴充功能，可以直接安裝 Obsidian Web Clipper：

  1. 開啟 Firefox for Android
  2. 前往 Firefox Add-ons 頁面搜尋「Obsidian Web Clipper」
  3. 安裝後功能與桌面版相同

iOS / Android：Obsidian App 分享功能

如果你只需要快速儲存 URL，最簡單的方法是：在任何 App 中「分享」網頁 → 選擇 Obsidian → 指定資料夾和標題。這不會提取頁面內容， 但對於建立待讀書籤已經足夠。

手機剪藏的現實建議：手機端因鍵盤輸入不便，建議以「書籤快存」為主，僅保存 URL + AI 摘要，回到電腦再做深度整理。不要在手機上試圖完成整個處理工作流。

本章小結

Obsidian Web Clipper 是知識管理流程中「收集」這一環的核心工具。 正確設定後，你的資訊流入口從「手動複製貼上」變成「一鍵剪藏 + AI 即時摘要」， 大幅降低了知識收集的摩擦力。

本章涵蓋了安裝設定、模板語法、四種剪藏類型對比、Inbox 到歸檔的整理工作流、 與 Readwise / Hypothesis 等工具的整合方式，以及手機端的多種剪藏方案。 下一章我們進入模板的進階設計——如何用黃金圈 Prompt 讓 AI 摘要更有洞察力、 如何建立針對不同內容類型的專屬模板，以及自動化書籍筆記整理的實戰案例。
